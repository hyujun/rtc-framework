# 포구 평가·분석 도구의 판정 규칙

포구 sim 평가 도구가 낸 숫자를 **어떻게 읽는가** 의 규칙과 그 이유다. 도구를 실행하는 방법은 [integrated_bringup/docs/catching-sim-trials.md](../../catching-sim-trials.md), 열 정의와 절차는 각 도구의 머리 docstring 이 갖는다. 이 문서는 docstring 에 적기 어려운 "왜 그렇게 읽는가" 만 둔다. 도구마다 H2 하나씩 두며, 새 도구 절은 끝에 H2 로 붙인다.

## integrated_bringup/tools

### 기록과 판정을 가른다

- `trial_results.json` 의 `final_outcome` 은 supervisor 가 **마지막으로 발행한 label** 이지 포구의 판정이 아니다. 새 cycle 이 시작되지 않은 투척에는 앞 투척의 label 이 그대로 남는다 (`iiwa7_leap` 에서 3 건을 44 건으로 읽은 적이 있다). 성공은 `catching_trials` 의 `truth_success` 로 센다. `unit_report.py` 는 둘을 따로 낸다.
- `summarize.py --unit` (N arm 기록) 은 **판정하지 않는다**: 대조군 · 비열등 한계 · PASS/FAIL 이 없고, 풀이 p99 가 예산 안인지 같은 것은 사실로 적는다. 판정 규칙(G-1)은 `--cf`/`--mpc` 형식만 갖는다. 기록에 판정을 섞으면 어느 결과를 보고할지를 고르게 되기 때문이다.
- arm (search × segment × 공) 은 플래그나 디렉토리 이름이 아니라 **unit 의 `mirror.txt`** (컨트롤러에서 되읽은 값) 에서 읽는다. `conditions.txt` 의 기대값(`expect_*`)이 미러와 다르면 거부한다. 라벨이 실제 실행과 어긋난 채 표가 만들어지는 것을 막는다.
- 컨트롤러 빌드가 unit 사이에 다르면(`controller_bin_sha256` 이 둘 이상) 차이가 빌드의 것일 수 있어 거부한다. 값 하나만 다른 unit 은 `--vary <미러>` 로 그 값을 arm 에 넣어 구분한다.
- 끊긴 풀이(코어가 기한에 끊은 풀이)의 시간은 풀이 시간 분포에 넣지 않고 개수와 비율로 낸다. 규칙은 `rtc_tools.analysis.planner_solves` 가 갖는다.

### 재시도와 host 부하

- 재시도는 **rig 실패**(`host_busy` · `estimator not activated` · `startup`)만 한다. 그 밖의 실패는 그 unit 의 투척이 원인일 수 있고, 다시 돌리면 어떤 결과를 기록할지를 고르게 되므로 실패한 자리에 남긴다.
- 성공률 판정에 쓰는 unit 은 `--host-watch abort` 로 돌리고, exit code 3 이면 같은 seed 로 unit 전체를 다시 돌린다. 시행 단위 무효 처리와 보충 투척은 모집단을 바꾸므로 하지 않는다. 근거는 [L8 §4.5](L8_bringup.md) · ID_INDEX D-S8-17.
- `detections[].processes` 는 원인 후보일 뿐 판정이 아니다. 목록이 비어도 sim 이 느렸으면 부하다.

### `probe` dump 가 열의 뜻을 바꾼다

`PROBE_DUMP=1` 로 돌린 unit 의 분석은 `catching_trials` 가 계획의 포구점이 dump 의 지평 점과 일치할 때 realtime − steady 를 다시 잡는다(`refine_wall_offset`). 그래서 `tc_stamp_minus_tc_ms` · `tc_axis_source` · `tc_axis` 가 dump 없는 unit 과 같은 규칙으로 계산된 값이 아니다. dump 있는 unit 과 없는 unit 을 짝지어 비교할 때는 `tc_axis_source` 를 먼저 본다.

### `docking_ident`

식별한 값(통과 평면 · lateral 집합 · 속도 집합 · 폐쇄 창)의 판정 규칙(유지율, 5 %p 하락 한계)과 출하값은 [L6 §4.6](L6_hand.md) 이 갖는다. 절차와 격자는 `report.py` 머리가 갖는다. 이 도구가 내는 값은 전부 provisional 이다 — sim 의 손 흡수·반발은 실기 값이 아니다. 폐쇄 시각은 두 축으로 읽는다: 폐쇄 명령에서 $s_{ent}$ 통과까지, 폐쇄 명령에서 원점 도착까지. 날릴 때의 `T_close_e2e` 가 이 축에 상수로 들어 있으므로 profile 의 값이 `selfcheck` 때와 다르면 `report.py` 는 상수 없는 꼴도 함께 적는다.

## rtc_tools

`rtc_tools` 의 분석 CLI 가 낸 열과 판정을 읽는 규칙이다. 실행 방법과 인자는 [rtc_tools/README.md](../../../rtc_tools/README.md) 가 갖는다. 아래 `S*` · `E*` · `G*` · `D-*` 는 이 디렉토리의 [ID_INDEX](../ID_INDEX.md) 와 L3 · L7 · L8 의 항목 번호다.

### 공통 규약

- **판정 도구가 아니라 측정 도구다.** `NOT_EVALUATED(<사유>)` 는 입력이 없어 계산하지 않았다는 뜻이고 통과가 아니다. 모르는 값은 NaN 이며 0 으로 대신하지 않는다.
- **로봇 상수가 코드에 없다** (ARCH-1). 한계 · 프레임 · 게인은 `--config-dir` 의 로봇 profile (`_base.yaml` → `sim.yaml` → `--overlay`, CM 과 같은 키 단위 병합) 과 러너가 `run_meta.json` 에 남긴 컨트롤러 미러에서 읽는다. 미러가 없으면 launch 와 같은 순서로 파일을 합성하고 출처를 요약에 적는다.
- **판정 대상은 `catching_trials` 가 낸 유효 시행이다.** 무효는 rig 실패뿐이고 (아래), 판정 실패 (plan 없음 · abort · 놓침) 는 유효한 실패다.
- 쌍을 짓는 비교는 `(kind, seed, sample_idx)` 로 같은 투척을 짝짓는다. 짝이 없는 시행은 따로 센다.
- 분위수는 nearest-rank 순서통계량이다. 표본이 100 미만이면 p99 는 최댓값이고 도구가 그렇게 적는다.
- 검정력 · 필요 시행 수 · 정확 검정은 합성 데이터의 positive control 로 도구 테스트가 고정한다 (`rtc_tools/test/`).

### plot_rtc_log: 로그 종류별 열과 figure

파일 이름과 열 지문으로 종류를 감지한다 (이름 표는 README). 컨트롤러 소유 진단 CSV 의 해석 규칙은 아래와 같다.

**`catching_diag.csv`** — 동적 포구 tick 레코드. 컬럼 지문은 `track_err_rad` + `ref_gamma`. 모든 tick 이 한 행이라 tick 간극은 드롭된 행이다.
- 내용: 슈퍼바이저 mode/reason, 입력 snapshot 의 token · 나이 · 지평, plan, L4 기준 (실현 가속도와 포화 전 요구값 둘 다), CLIK status/solve_us, `q_c` 대 `q`. 산출은 `catching_diag.png` (E-STOP · fault latch 구간 음영) 와 통계.
- 패널은 로그에 그릴 것이 있을 때만 생긴다: 위치 (soft-catch 기준 `ref_x`, plan 의 `p_c`, `mode: mpc` 에서 따르는 구간의 목표 `segment_p_d` 는 일점쇄선 `seg_*`) · 가속 (soft-catch 기준이 돈 로그만) · 추종 오차와 solve time · 구간 feedforward `segment_v_ff` · segment lane (`segment_event` 를 이름으로, 거부는 맨 위 줄, 매 tick 나는 `repeat` 은 뺀다, 전환 게이트의 $\rho$ 는 오른쪽 축) · 명령 kinematics (`q_cmd_*` 를 기록된 시간축으로 미분한 관절 최대 속도 · 가속 · jerk, 5 행 box 평활, log 축, 바닥 1e-3 아래는 그리지 않는다: 멈춘 명령은 반올림 잡음으로 미분된다) · 모드.
- `segment_*` 열이 없는 로그와 `closed_form` 로그 (열이 전부 0) 는 segment 패널 없이 그려진다. 열 이름이 `decel_*` 인 옛 recording 은 별칭 표 한 벌 (`rtc_tools/utils/catching_keys.py`) 로 새 이름으로 읽고, 옛 이름과 새 이름이 섞인 파일은 거부한다.
- 통계: `mode: mpc` 로그는 구간을 따른 tick 을 "법칙이 돈 tick" 으로 세고, segment 블록 (따른 tick · 구간 수 · 사건과 거부의 이름별 수 · 전환 $\rho$ p50/p95/max) 을 낸다.

**`planner_events.csv`** — 계획기 스레드의 non-idle wake 당 한 행. 컬럼 지문은 `n_in_window` + `rank_error_budget`. 시간축은 `wake_ns` 기준 첫 행 이후 경과초다 (이 채널에 `t_relative_s` · `t_wall_ns` 가 없다).
- 내용: 후보 funnel (`n_in_window` / `n_ik` / `n_pass`), judgement-reject 히스토그램, 선택 후보의 rank-gate 실패 비트마스크 (§4.8 rollout gate 포함), 스위칭 `decision`, wake 의 `outcome` (`idle` · `no_input` · `published` · `superseded` · `held`; plotter 는 옛 로그를 위해 `held_replace_unsupported` 도 순서에 둔다), `recv_to_publish_ms` (publish 된 행만).
- `planner_events.png` 는 search/IK/rollout 시간 · latency · funnel · reject 히스토그램 · outcome/decision 이벤트 · rank-gate 실패의 6 단이다. 로그에 열이 있을 때만 패널이 붙는다:
  - segment 계획기가 돈 세션: `segment_outcome` (풀이 종류 `segment_kind` 로 색) · `segment_solve_us` 와 QP 반복 수 · 포구 노드 (`segment_catch_pos_err` mm · `segment_catch_axis_err` deg · `segment_catch_v_rel` m/s · `segment_catch_gamma`, 첫 풀이의 `segment_x0_speed`).
  - `mpc_docking` 세션: 행 그룹별 위반 (`segment_viol_*`, 로그 축, 불능으로 끝난 풀이의 그룹은 고리) 과 KKT 잔차 · 포구 노드의 $c_N$ 과 $\sigma_s$ · $\sigma_t$ · lateral / timing 행의 부호 있는 여유 (`segment_chance_*`).
  - `nlp` 탐색 세션: 후보 수 (`nlp_n_lattice` → `nlp_n_valid`) · wake 의 사유 (`nlp_reason`) · 고른 후보의 $\Phi$ / $J^\star$ 와 가장 느린 후보 풀이.
- **코어가 기한에 끊은 풀이** (`segment_core_reason` == `deadline`) 는 solve 패널에서 빈 삼각형이고 통계 분포에 넣지 않는다 — 그 시간은 끊긴 시각이지 풀이 시간이 아니다. 판정은 아래 `planner_solves`. 보류된 교체의 첫 풀이 (`replacement_*`) 는 같은 패널의 마름모다.
- `nlp` 의 가장 느린 후보 풀이는 wake 행으로 가를 수 없다: `nlp_rej_deadline` > 0 은 코어가 끊은 풀이 · 기한을 넘겨 끝난 풀이 · 늦게 끝난 wake 의 유효한 후보를 모두 포함하므로 "끊겼을 수 있다" 고만 적는다.
- 통계: 종류별 건수 · 게시 수 · solve p50/p99/max, `segment_outcome` 분포, 게시된 구간 사이 간격, `search_valid` 대 `plan_valid` (탐색이 plan 을 냈는데 게시하지 않은 wake 수 — 구간 계획기는 plan 을 첫 구간과 함께만 내고, 채택 뒤 탐색이 낸 plan 은 `held` 로 기록만 한다). 풀이를 종류 · outcome · 코어 사유 · 불능 그룹으로 묶은 표, `nlp` 의 wake 사유와 검사별 탈락 수, 교체 시도가 끝난 자리 (`replace_step`) 를 더한다. 이름 열 `segment_outcome` · `segment_core_reason` · `segment_kind` 는 문자열이다.

**`dualarm_diag.csv`** — 다중 frame CLIK 의 tick 레코드. 컬럼 지문은 `clik_ran` + `<task>_err_lin` 이고 `accel_*` 분기보다 먼저 판정한다.
- 컨트롤러가 도는 모든 tick 이 한 행이다. `tick` 은 CM loop counter 라 다른 컨트롤러가 활성인 동안에도 세므로, 간극은 **떨어진 행이거나 이 컨트롤러가 돌지 않은 구간**이다. 통계가 간극 뒤 첫 행으로 가른다 (`reseeded` 이거나 시드 전 hold 면 돌지 않은 구간, 아니면 `DROPPED ROWS`). 선은 간극에서 끊는다.
- 과제 수 · 관절 수는 헤더에서 읽는다: 과제 = `<x>_err_lin` · `<x>_err_ang` · `<x>_valid` 가 모두 있는 접두 `<x>` (헤더 순서 = 설정 순서), 관절 = `q_cmd_` 뒤. figure 는 과제마다 행이 늘어난다.
- figure: `dualarm_diag_solver` (풀이 시간 · 반복 · status · 비정상 tick · `qp_fail_streak` · `track_err`) · `_task_error` (기준 대 명령 오차, 목표가 바뀐 tick 에 점선, 기준이 움직이는 구간 음영) · `_task_pose` (x · y · z 의 ref / cmd / meas 와 cmd 대 meas 차이) · `_limits` (binding 가속 행 · 과제별 되먹임 상한 · 제동 한계가 건 관절 수) · `_goals` (누적 목표 계수, 계수가 하나라도 움직인 로그에서만) · `_joint_cmd`.
- 값은 **그것을 계산한 tick 에서만** 그리고 센다 (나머지의 0 은 계산 안 한 0): 풀이 시간 · 반복 · status 는 QP 에 도달한 tick (`reached_solve` — 입력이 거부된 호출은 `clik_ran` = 1 이지만 풀이 값이 없다), `track_err` 는 `clik_ran` = 1 인 tick, 과제 열은 `<task>_valid` = 1 인 행. 목표 점선은 `goal_sequence` 가 0 이 아닌 값으로 바뀐 tick 만이다 (재시드의 0 복귀는 목표가 아니다). `hold` ≠ 0 구간은 원인별로 음영.
- `<task>_err_*` 에는 서보 지연이 없고 `_task_pose` 의 cmd 대 meas 는 시간을 밀지 않아 지연이 그대로 들어 있다. `brake_*` mask 의 bit 는 모델 속도 index 라 관절 이름으로 풀지 않는다 — 통계가 bit 번호를 낸다.

**그 밖의 종류**
- `wbc_diag`: per-tick TSID/QP 진단 (solve time · $\lambda$ · 수렴 · grasp). `grasp_diag`: Force-PI 서보 + 강성 추정 진단.
- `pull_estimator`: in-plane pull-force 추정 (raw + filtered force, in-plane · magnitude · directional, friction util · leakage, validity 플래그, 관측된 파지 형태 `opposing_mask`). 4×1 sharex 단일 figure + 통계.
- `compliance_diag`: §7 task-admittance 진단 (소비된 wrench, source verdict, FSM · $\alpha$, $\tilde x$ · $\nu_c$, 파라미터 스냅샷). 지문은 `x_tilde_`. **통계 전용, figure 없음** — envelope · freshness · bias 수치가 산출물이다.
- `momentum_observer`: 일반화 운동량 관측기 잔차 `r_<joint>` · ‖r‖∞ · 게이트, Layer 2A payload wrench/질량, Layer 2B 관성 회귀. `momentum_observer.png` 와 (2A/2B 가 구성된 run 에서만) `momentum_payload.png`.
- `wbc_log`: `<dev>_state.csv` 는 파일명만으로 generic state_log 와 구분되지 않는다. `accel_*` 열 지문으로 열 fallback 단계에서 분류하고, state_log 의 robot/motor 플롯에 가속도 · SE3 · fingertip force 플롯을 더한다.

**힘만 있는 손 (`sensor_layout.values_per_group: 0`)**: 기압/ToF lane 이 없는 핸드는 CSV 에 `<name>_raw_*` / `<name>_filt_*` 블록이 생성되지 않는다. 그 부재를 gate 로 삼아 기압/ToF figure 와 `device_ft_output` 대신 단일 `fingertip_force.png` 를 만든다 (N 행 × 2 열: 좌 `Fx/Fy/Fz` raw + LPF + guard hold 구간, 우 `‖F‖`).
- delta-spike guard 오버레이는 `ft_*_fx_guarded` / `ft_*_force_guard_rejected` 열이 있는 세션에서만 그려진다 (파선은 guard 가 raw 를 대체한 tick 만). guard 이전 세션은 오버레이를 생략한다.
- `‖F‖` 는 **필터된 성분의 norm** 이다 (컨트롤러가 임계와 비교하는 값과 같다).
- 시간축은 전 subplot 공유, y 축은 열 단위 공유다 (좌측은 부호 있는 성분, 우측은 비음수 크기).

**타이밍 CSV 의 run 선택**: 세션 디렉토리는 분 해상도라 같은 분의 재기동이 같은 파일에 append 된다. `run_id` 가 여러 개면 마지막 런만 그리고 버린 런을 stdout 에 적는다 (파일 전체로 `n / span` 을 내면 어느 런에도 없던 레이트가 나온다).

### derive_accel_limits

가속 데이터 없이 토크 한계만 있을 때, 팔 상태 $(q,\dot q)$ 표본마다 $\sum_j |M_{ij}| a_j \le \eta_\tau \tau_{max,i} - |g_i| - |c_i|$ 를 만족하는 최대 $a = s\,w$ 를 구하고 (최악 부호 결합의 충분조건) 전 표본의 최소값을 상수 box 로 낸다. 보수적인 이유는 최악 부호 조합이라는 것과 자세를 따르지 않는 관절별 상수 하나라는 것이다. 표본 최소값은 표본 수에 따라 계속 내려가므로 최악 표본 10 개에서 박스 안 국소 최소화 (Powell) 로 정제한다. 판정식은 [L3](L3_planner.md) §4.3.
- 출력은 분석 산출물이다. 컨트롤러가 읽는 box 는 `catching/search_grid.yaml` 의 `robot.arm.qdd_max` 이고 이 도구는 그 값을 정할 때 쓰는 계산이다.
- 입력: 로봇 config 의 `devices.<group>.joint_state_names` · `joint_limits.{max_torque,max_velocity,position_*}` 와 `urdf.package/path` (xacro 확장). `--eta-tau` 는 기본값이 없다 (결정 사항).
- 표본 범위 기본값은 관절 한계 box 전체 (URDF ∩ config) 와 $\pm$ max_velocity 이고 `--q-center/--q-halfwidth` 로 좁힌다. 손 관절은 URDF 중립 자세 · 속도 0 으로 고정하고 손 가속 결합 $\max|M_{arm,hand}|$ 는 provenance 에만 적는다.
- 퇴화 ($\tau_{dyn} \le 0$ 인 표본, 또는 $s^\star$ < `--min-accel`) 면 `adopted: false` 로 쓰고 exit 2. 교차 검증 실패는 exit 3.
- 교차 검증: `--check rnea` (부호 패턴 전부에 대해 RNEA 토크 $\le \eta_\tau \tau_{max}$), `--check mujoco --mjcf <xml>` (`mj_inverse` 로, MJCF armature · damping 포함, 접촉 · 관절 한계 구속은 끔, actuator forcerange 이하인지). mujoco 는 venv 에만 있으므로 `.venv/bin/python -m rtc_tools.analysis.derive_accel_limits` 로 실행한다.

### clock_phase · hand_close · vision_lane

**clock_phase** (D-3, S3.1a): D-3 는 비율 (RTF) 이 아니라 시행별 clock 위상 오차로 판정한다 (L8 §4.5). `rtc_mujoco_sim` 의 `clock_lane` CSV 에서 발사 시각을 원점으로 $\delta(t) = (\text{steady} - \text{steady}_0) - (\text{sim} - \text{sim}_0)$ 를 쌓아 시행별 $\delta_{max} = \max|\delta|$ 와 max pause (한 step 의 $\Delta$wall $-$ $\Delta$sim 최대) 를 낸다.
- 창은 **비행 구간**이다 (lane 의 `launch_seq` · `ball_active` 로 자르므로 투척 사이 대기가 오차로 잡히지 않는다).
- $\delta$ 는 판정이 아니라 **공변량**이다 (D-S8-4 (c)). 분포 ($\delta_{max}$ · max pause 의 p50/p95/max) 를 내고 `--eps-mm` 을 주면 그 $\varepsilon$ 에서 L8 §4.5 유효 조건을 만족하는 시행 비율을 "valid under eps — COVARIATE" 로 병기한다. 95 % 를 통과시키는 $\varepsilon$ 는 측정의 역산인 **제안값**으로만 낸다.
- 지정 발사라 시드 RNG 를 소비하지 않고 모든 시행이 같은 방출 상태다 — 시행 간 차이는 투척 분산이 아니라 기계의 차이다. lane 의 누적 drop 을 그대로 보고한다 (drop 이 있으면 꼬리가 정확히 빠진 채 분포가 멀쩡해 보인다).

**hand_close** (S4.2): L6 §4.2 의 $\rho(t) = \min_{i\in C}\big((q_i - q_i^{pre}) s_i / |q_i^{cls} - q_i^{pre}|\big)$ 와 $T_{close,e2e}(\eta) = \inf\{t - t_{cmd} : \rho \ge \eta\}$ 를 포구 컨트롤러의 `<hand>_state.csv` 에서 낸다. 러너가 손 그룹에 preshape↔closed 계단을 N 회 쏘고, 분석기는 command lane 으로 시행을 자른다 (`command_*` 가 바뀐 첫 행이 $t_{cmd}$).
- 프로파일은 컨트롤러의 **읽기 전용 파라미터**에서 읽어 JSON sidecar 로 떨군다 (출하 YAML 이 아니다). 분석은 그 run 의 컨트롤러가 실제로 읽은 값으로 한다. `dt` (`control.dt` 미러) 도 같다. dt 는 tick 축과 드롭 판정을 둘 다 스케일하므로 추정한 dt 는 자기를 검사하지 못한다 — sidecar 에 `dt` 가 없으면 tick 축을 **신뢰 불가**로 찍는다.
- 시간축을 둘 보고한다: `steady` (`t_relative_s`, lock-step sim 에서는 호스트 스톨 포함) 와 `tick × dt` (sim 시간, 결정적). 차이가 스톨이다. CSV 행이 드롭되면 tick 축이 어긋나므로 샘플 간격을 검사한다.
- 시행 구간은 `pre` / `close` / `other` 로 분류한다. 자기 travel 의 25 % 밖이면 `other` 이고, `other` 는 시행을 끝낼 수는 있어도 시작하지는 못한다 (활성화 시점의 hold 자세나 `q_open` 계단이 유령 시행을 열지 않게).
- $\rho$ 는 **최소**다. 한 손가락만 늦어도 손 전체가 못 감싼 것이다. caging 집합은 프로파일이 정한다 (닫힐 때 오히려 펴지는 관절을 넣으면 진행으로 오독한다). p99 는 순서통계량이다.
- 축마다 표본 표준편차 ($n-1$) 와 `mean − T_close_lead` 를 낸다. 시퀀서가 $t_c - T_{close,lead}$ 에 닫으므로 그 차이가 폐쇄가 $t_c$ 뒤 어디에 끝나는가 — 폐쇄 창을 쓰는 계획기의 $\delta_0$ 다. `T_close_lead` 는 sidecar 의 `T_close_lead_at_run` 이고, 없는 옛 sidecar 는 `T_close_e2e_at_run` 으로 대신하며 "falling back" 이라고 찍는다. 둘 다 없으면 "계산할 수 없음". $T_{close,e2e}$ 는 잰 폐쇄 시간이고 명령 시각을 정하지 않는다 (L6 §4.3). tick 양자화 `dt / sqrt(12)` 는 표준편차 옆에 적고 더하지 않는다.

**vision_lane** (S3.4, D-4): `ball_perception` 의 `prediction/trajectory` (PointCloud2) 를 **필드 이름으로** 디코딩한다 (이름 · offset · datatype · count · `point_step` · endianness 가 하나라도 다르면 거부). 프로브 CSV 에서 발행 주기 · N · 지평 (TBD-VIS-04), `frame_id` (VIS-06), 측정 손실 뒤 `validity` (VIS-07), best_effort 대 reliable 구독 손실 (VIS-08) 에 답하고 $T_{det}$ (발사 → 첫 VALID 예측, S3.6) 을 더한다. **측정만** 한다. 정책은 S5.2 몫이다.
- 프로브는 예측 토픽을 best_effort · reliable 둘 다 KEEP_LAST(1) 로 구독해 받은 것을 identity 로 비교한다 (개수가 같아도 다른 메시지일 수 있다). 릴레이는 stamp 를 건드리지 않는다 (지연은 전송 지연으로 보인다). estimator 프로파일의 `input.topic` 을 릴레이 출력으로 돌린다.
- `sim_estimator_node` 는 `debug.enabled_topics` 에 `prediction/trajectory` **만** 있으면 샘플을 기록하지 않아 발행이 0 건이다. 다른 debug 토픽을 하나 이상 같이 켠다.
- **$T_{det}$** (`detection_latencies`): 비행은 truth lane 의 **침묵**이 가른다 (`--flight-gap-s`, 기본 0.3 s — 시뮬레이터는 공이 park 상태면 아무것도 발행하지 않는다). 발사 시각은 그 비행의 첫 ground-truth 샘플이고 양자화는 공 발행 주기 하나다. 두 축을 각각 한 시계 안에서 낸다 (D-2): `recv` (프로브 steady, 전송 포함 = 소비자 체감) 와 `stamp` (발행자 stamp, 전송 제외). stamp 축은 sim rig 전제 (truth · camera 를 같은 문장에서 stamp 하고 estimator 가 capture stamp 를 예측에 복사) 위에서만 한 시계다. 발사 전부터 VALID 이던 트랙 (유령, VIS-07) 은 generation 이 그때 것이라 검출로 세지 않는다. 검출이 없던 비행은 버리지 않고 NaN 으로 보고한다.
- `--dump` (S8-A, 기본 off): 예측 메시지마다 모든 지평 점을 한 행씩 (`point_index` · `generation` · `snapshot_sequence` · 점별 `validity` · 6×6 공분산 `cov_rc`) 과 추정기 `debug/innovation` (`Vector3Stamped`, capture stamp) · `debug/nis` (`Float64`, stamp 없음 — 프로브의 steady · wall 수신 시각만) 을 각자의 CSV 로 쓴다. G8-C2 (A⊥B) 의 입력이며 $\bar\nu$ 생산자가 아니다 (D-S8-7 (a)).

### catching_trials

`catching_sim_trials` 한 run 이 남긴 컨트롤러 세션 CSV, 러너의 trials dir (`trial_results.json` + `run_meta.json` + 시행별 truth CSV), `sim_lanes:=true` 로 켠 clock · 접촉 lane 을 시행당 한 행으로 잇는다. 투척 목록 (`--throws-file`) 으로 던진 시행의 행은 그 투척의 `throw_id` 를 갖는다 (`catch_search_map --sim-trials` 가 오프라인 지도와 잇는 키). 출력은 `catching_trials.csv` · `catching_trials_summary.json` · `hand_hold_window.csv`.

**시각 정렬 (`time_alignment`)**. sim-sync 에서 컨트롤러의 `t_relative_s` 는 `iteration × dt` 라 sim 시간축과 세션 상수 $c = \text{sim} - t_{rel}$ 만큼만 다르다. clock lane 이 있으면 모든 시행을 lane 기준으로 놓는다.
1. 발사 짝짓기는 러너의 `launch_wall_time` (CLOCK_REALTIME) 대 lane 첫 비행 행 `steady_ns` (CLOCK_MONOTONIC) 의 상수 하나 (부팅당 realtime − monotonic) 로 한다.
2. $c$ 는 commit tick 마다 `planner_events.csv` 의 `wake_ns + lead_s` (계획 $t_c$ 의 steady 시각) − diag `plan_t_c_s` 로 그 tick 의 steady 시각을 얻고, 그 직전 lane 행의 sim 시간 − tick 의 `t_relative_s` 로 구한다 (중앙값 · spread 보고).
3. `t_launch` = lane 발사 sim 시간 (첫 비행 행 − 한 step) − $c$. `t_end` = `mode_log` 벽시계 → steady → sim (lane 보간) − $c$.
4. truth · 예측 · eval sample 의 ball stamp 는 발사 기준 sim 시간축이라 `stamp − (anchor − t_launch)` 로 옮긴다. anchor 는 기록 `pos` 와 같은 첫 truth 행의 stamp (아니면 lane 추정, `stamp_anchor`). `--probe-dump` 가 있으면 계획의 `p_c` 가 계획 snapshot 의 점과 일치하는 stamp − 계획 steady $t_c$ 로 offset 을 정확히 다시 잰다.
- 러너의 `wall_t_relative_offset` (RTF < 1 이면 $(1 - \text{RTF}) \times$ 시행 길이만큼 흐른다) 은 lane 이 없을 때만 쓴다 (`median_offset`).
- 행 열: `time_alignment` · `stamp_anchor` · `t_launch` · `t_end` · `hold_verdict` · `abort_in_window` (그 창의 mode 경로: HOLD → RETREAT 판정 tick 이 있는가, `ABORT_SAFE` tick 이 있는가. `catching_decel --success hold` 가 읽는다) · `stamp_minus_t_rel_s`.
- truth 파일은 `trial_results.json` 옆의 것이 먼저다. 러너가 절대경로로 적은 truth 가 다른 run 의 파일을 가리킬 수 있어, 첫 stamp 가 그 시행의 `launch_wall_time` 에서 5 s 넘게 떨어진 파일은 거부한다. truth 파일 없이 유효인 시행은 `validity.valid_without_truth_file` 에 나열한다 (실패로 세지만 파이프라인 결함이다).

**무효 판정**. 무효는 rig 실패뿐이다. 모든 시행에 `invalid_reason` 한 개 (빈 문자열 = 유효) 를 우선순위대로 붙인다.

| 사유 | 조건 |
|---|---|
| `srv_refused` | 기록 `accepted` 거짓 |
| `not_launched` | accepted 이고 `n_truth_rows == 0` (필드가 없는 구 기록은 판정 안 함) |
| `controller_silent` | `wall_t_relative_offset` 없음, 또는 시행 창에 diag 행 0 |
| `lane_drop` | clock lane 에 이 시행과 짝지어진 발사 세그먼트 없음, 또는 시행 행에서 `dropped_total` 증가 |
| `sim_stall` | 시행 행 안 연속 `sim_time_sec` 간격 > 5 × nominal step (lane 전체 간격의 중앙값) |

그 외 (plan 없음 · abort · HAND_TIMEOUT · 순환 미종결 · Missed) 는 유효한 **실패**다. lane 규칙의 시행 행은 그 `launch_seq` 를 단 모든 행 중 발사부터 시행 끝 (+ diag 창 margin) 까지다 (`launch_seq` 는 다음 발사까지 유지되므로 자르지 않으면 다음 투척의 homing 이 들어간다). `dropped_total` 은 누적이라 세그먼트 첫 행 바로 앞 행과 비교한다. clock lane 이 없으면 lane 규칙은 평가하지 않고 요약에 `NOT_EVALUATED` 로 적는다.

**요약 모집단**. `validity` 블록 (`n_total` · 사유별 `n_invalid` · `n_valid` · `lane_rules_evaluated`). `truth` · `medians` · `d3` · `g3d` · `gate_map` · G8-C3 · G7-B3 는 **유효 시행만** 센다. `truth` 에는 `lower_975` (Wilson $z$ = 1.96, 97.5 % 단측 하한) 와 `itt` (무효를 실패로 센 `n_total` 기준 성공률 · Wilson · 하한) 가 있다. `--floor` 를 주면 `truth.verdict` 가 PASS / FAIL (`lower_975 ≥ floor`) 이고, `--n-valid-target` 을 주고 `n_valid` 가 모자라면 `INSUFFICIENT_N`.

**truth 성공** (G8-D, L8 §9). HOLD 끝 (첫 RETREAT tick) 부터 대기 자세 release (손 위상 RELEASE) 까지 모든 truth 샘플이 catch frame 에서 `--hold-radius-m` (기본: 프로파일의 공 지름) 안에 있다. 슈퍼바이저 판정 대비 혼동행렬과 Wilson 구간을 낸다. 첫 손–공 접촉 episode (접촉 lane) 는 충격량 · 최대 접촉력 · 지속 · 접촉 속력이다 (손 토크는 sim forcerange 클램프라 판정하지 않는다).

**$t_c$ 분해**. 첫 COMMITTED tick 에서 $t + $ `plan_t_c_s` 를 $t_c$ 로 잡고 `‖FK(q_cmd) − ref‖` (CLIK, `clik_mm`) · `‖FK(q_meas(t_c)) − FK(q_cmd(t_c − T_lead))‖` (서보, `servo_mm`) · `‖p_c − p_true(t_c)‖` (예측, `pred_mm`) · `ref_vs_true_mm` · `total_mm` 을 낸다. 공 도착 − $t_c$ (`arrival_ms`), 계획 $\gamma_f$ (`plan_gamma_f` — `ref_gamma` 는 DECEL 진입 tick 에 1.0 으로 뛴다), 첫 plan 지연, 시행 순환 안의 APPROACH 교체도 낸다. 공이 $t_c$ 전에 로봇에 맞으면 truth 를 첫 접촉에서 자르고 직전 0.25 s 이차 적합을 $t_c$ 로 외삽한다 (`truth_extrapolated_ms` 에 거리 기록).
- **`t_c` 열의 축 (`tc_axis`)**: `t_c` 열은 sim 축 tick 에 steady 시계로 센 잔여 시간을 더한 값이라, commit 과 포구 사이에 sim 이 벽시계보다 느리면 공이 `p_c` 에 닿는 순간에서 벗어난다. 이 열에서 읽는 분해는 다른 순간의 값이다. `tc_stamp_minus_tc_ms` (stamp 축 $t_c$ − 열) · `tc_axis_source` (`plan_point`: probe dump 의 계획 snapshot 점, `planner_wake`: 계획 steady $t_c$ + lane 의 realtime − steady) · `tc_axis` = `ok` / `shifted` (차 > `--tc-shift-max-ms`, 기본 5 ms) / `unknown` (판정 불가 — 맞다는 뜻이 아니다) / 빈 값 (commit 없음). 요약 `medians` 의 해당 열은 `shifted` 행을 빼고 내며 `tc_axis` 블록이 `n_ok` · `n_shifted` · `n_unknown` · `shifted_trials` · 차 p50/p95/max 를 센다. 행 단위로 읽을 때는 `tc_axis` 를 함께 본다. 부하를 막는 쪽은 러너의 `--host-watch` 다.
- **lead** (S8-B): `joint_cmd.lag.lead_enable` 이 켜지면 RT 가 참조를 `now + T_arm` 에서 샘플하므로 tick $t$ 의 `q_cmd` · `ref` 는 $t + T_{arm}$ 을 겨냥한다. 명령 쪽 (서보 · CLIK · `ref_vs_true`) 은 $t_c - T_{lead}$ tick 에서 읽는다. $T_{lead}$ 는 diag `t_arm_s` 열 → 러너 미러 (`joint_cmd.lag.*`) → 0 순이고, 열과 미러가 다르면 다른 세션의 trials dir 로 보고 거부한다. 같은 tick 의 `‖FK(q_meas) − FK(q_cmd)‖` 는 `cmd_meas_gap_mm` 로 기록만 한다 (lead on 에서 의도된 선행이 서보 악화로 읽히므로). lead off 에서는 둘이 같다.
- **서보 지연 $\hat\tau$**: 관절별 1차 지연 최소제곱 ($q_{cmd} - q_{meas} \approx \tau\,\dot q_{meas}$, 움직이는 tick) + 시행 클러스터 부트스트랩 CI · $R^2$. 속도 상호상관은 1차 지연의 $\tau$ 를 주지 않아 제공하지 않는다.
- **기준의 출처 (`ref_source`)**: 분해의 "기준" 은 그 시행의 법칙이 CLIK 에 준 것이다. lead tick 에 `segment_following` = 1 이고 `segment_p_d_*` 열이 있으면 `segment` (`mode: mpc`), 아니고 `ref_valid` = 1 이면 soft-catch 기준 `ref_x` (`soft_catch`, `closed_form`), 둘 다 아니면 `none` 이고 `clik_mm` · `ref_vs_true_mm` 는 NaN 이다 (법칙이 돌지 않은 tick 의 `ref_x` 는 0 벡터라 기준으로 읽으면 CLIK 오차가 catch frame 원점 거리가 된다). 세 항 (`ref_vs_true_mm` · `clik_mm` · `servo_mm`) 은 두 planner 에서 같은 뜻이다. 요약 `ref_source` 는 값별 시행 수.
- **$t_c$ 의 명령 (`cmd_*`)**: FK(`q_cmd`) 만으로 (측정도 기준도 쓰지 않는다) lead tick 에서 명령 속력 `cmd_speed_tc` [m/s] · 속력 변화율 `cmd_dvdt_tc` [m/s², 양수면 아직 가속 중] · 가속도 크기 `cmd_accel_tc` [m/s²], 첫 APPROACH tick 부터 명령 속력이 0.02 m/s 를 넘는 첫 tick 까지 `cmd_hold_s` (`mpc` 는 첫 구간의 node 0 을 기다린 시간, `closed_form` 은 ≈ 0), 거기서 lead tick 까지 `cmd_move_s` 를 낸다. 지연이 있는 위치 서보는 가속 중인 명령에 $\tfrac12\tau^2 a$ 를 남기고 시간 lead 는 그것을 보상하지 않으므로 이 열이 `servo_mm` 의 원인 쪽 관측량이다. 미분은 기록된 `t` 축의 중앙 차분이고 가속과 $d|v|/dt$ 는 5 행 box 평활이다 (`rtc_tools.utils.smoothing`, `catching_diag.png` 의 명령 kinematics 패널과 같은 kernel). `cmd_hold_s` 를 뺀 넷은 `tc_axis` 가 `shifted` 인 행을 중앙값에서 뺀다.
- **segment lane (`segment_*`)**: diag 의 segment 블록에서 시행당 따른 구간 수 `segment_n_followed`, 사건 수 `segment_admitted` · `segment_replaced` · `segment_switches` · `segment_gate_refused` (전환은 `switched` 와 `plan_switched` 를 함께 센다. `segment_admitted` 는 `admitted` 만 세고 `pair_admitted` 는 세지 않는다), box 에서 기다린 횟수 `segment_deferred` 와 가장 긴 것 `segment_deferred_max_ticks`, 옛 `catch_box` 거부 `segment_workspace_refused` (RT 가 그 검사를 뺀 MD-73 뒤 로그에서는 0), 나이로 버려진 구간 `segment_aged`, 첫 전환의 $\rho$ `segment_rho_first` 와 그 뒤 전환의 최댓값 `segment_rho_replan_max`, 첫 APPROACH 부터 첫 전환까지 `segment_wait_node0_ms`. **tick 이 아니라 사건을 센다** (대기 · `aged` 는 매 tick 반복되므로 연속 tick 을 하나로 센다. node 0 대기는 APPROACH 에서 끝나지 않으므로 APPROACH tick 만 세면 짧게 읽힌다). 열이 없는 diag 는 전부 NaN, 열이 있는 `closed_form` 시행은 0 (ρ · 대기는 NaN). 요약 `segment_lane` 은 구간을 하나라도 따른 시행이 있을 때만 생긴다.
- **catch frame 분해 (`cf_*` · `ent_*`)**: $t_c$ 의 gap 을 노름이 아니라 **측정 catch frame 의 벡터**로 쪼갠다. $p_{true}(t_c) - \mathrm{FK}(q_{meas}(t_c)) = [p_{true} - \mathrm{ref}] + [\mathrm{ref} - \mathrm{FK}(q_{cmd})] + [\mathrm{FK}(q_{cmd}) - \mathrm{FK}(q_{meas})]$ 의 네 항 (`tot` = `ref` + `clik` + `servo`) 을 `cf_<항>_{x,y,s}_mm` 로 낸다 ($x, y$ 는 lateral, $s$ 는 접근축 +z, 공 쪽에서 본 부호라 `tot` 은 손 안의 공 중심 좌표다). **날 좌표**다: 계획이 겨냥한 점 (docking 풀이는 $s = s_{ent}$, lateral 집합 안, 나머지는 원점) 을 빼지 않는다. 손의 포구 집합 (`catching.robot.hand.docking` 의 `s_ent` · `lateral.{n_faces,faces_a,faces_b,rho_ref}`; 없거나 TBD 면 아래 열은 NaN) 이 있으면 `cf_tot_lateral_margin_mm` · `cf_ref_lateral_margin_mm` (lateral 집합 margin $\min_i(b_i - a_i\rho)$, 양수면 안) 과 **입구 평면 통과** 를 낸다. 통과는 $t_c \pm$ `arrival_window` 의 tick 마다 자유비행 공을 측정 catch frame 에 놓고 $s$ 가 $s_{ent}$ 를 내려 지나는 ($t_c$ 에 가장 가까운) 순간을 두 tick 사이에서 보간한 것이다: `ent_cross_ms` (그 순간 − $t_c$; docking 의 $t_c$ 는 계획된 통과 시각이라 시각 몫이다) · `ent_x_mm` · `ent_y_mm` · `ent_lateral_margin_mm` · `ent_c_m_s` · `ent_v_perp_m_s` (손에 대한 공의 closing · lateral 속력, ±5 tick 차분). 이 열들도 `t_c` 열에서 읽으므로 `tc_stamp_minus_tc_ms` 가 크면 접근축 좌표에 공의 그 시간 동안의 진행이 섞인다. 요약 `catch_frame`: 읽은 집합, $t_c$ 와 통과점에서 집합 안에 든 시행 수, `last_seg_wake_join` 의 수, 중앙값 (commit 한 시행이 10 개 미만이면 `NOT_EVALUATED(n < 10)`).
- **마지막 구간의 wake (`last_seg_*`, `--clock-lane` 필요)**: 팔은 RT 가 마지막으로 전환한 구간으로 포구에 닿고 그 풀이가 아는 공은 그 wake 만큼 낡았다. lead tick 에 따르던 `segment_seq` 를 `planner_events.csv` 에서 **이 시행 안 · $t_c$ 앞에 그 번호를 게시한 행**과 짝짓는다: `last_seg_seq` · `last_seg_kind` (`first` / `same` / `advance`) · `last_seg_k`, `last_seg_wake_to_tc_ms` ($t_c$ − wake), `last_seg_solve_ms`, `last_seg_slack_c` · `last_seg_slack_v` (통로 · closing envelope slack), `last_seg_elastic_max` · `last_seg_viol_max` 와 그 행 군 (`_group`). 그 wake 가 읽은 vision snapshot 은 `wake_snapshot` 이 정한다. 계획기의 `snapshot_sequence` 는 탐색을 돈 wake 만 적으므로 없으면 **wake 시각 + 6 ms 까지 tick 이 읽은 가장 새 snapshot** 을 쓴다. `last_seg_wake_join` 은 `planner` (계획기 기록, 그 구간의 tick 이 같은 것을 읽음) / `exact` (구간의 tick 이 한 snapshot) / `ambiguous` (구간 안에 새 snapshot 이 도착 — 새 것을 준다) / `conflict` (계획기 기록을 읽은 tick 이 없음) / `none`. `last_seg_snapshot_seq` · `_gen` 은 probe dump 의 키, `last_seg_pred_age_ms` 는 그 snapshot 을 컨트롤러가 받은 뒤 wake 까지 (diag `input_age_s`, 추정기의 지연은 들어 있지 않다).
- **정지의 직선 이탈 (`stop_*`, `--clock-lane` 필요)**: 포구 뒤 손이 공의 직선에서 얼마나 벗어나 멈추는가. 정지의 끝은 따르던 구간이 마지막 노드를 지난 순간이다: $t_c$ 의 명령 뒤로 diag `segment_held` 가 처음 서는 tick 이 명령 축의 그 순간이고 팔은 lead 하나 뒤 (`t_end`) 에 거기 있다. 직선은 그 tick 에 따르던 구간 (`stop_seq`) 의 풀이가 `planner_events.csv` 에 적은 것이다 (`segment_stop_line_*`). 실행: `stop_exec_dev_end_mm` (`t_end` 의 FK($q_{meas}$) 가 직선에서 떨어진 거리) · `stop_exec_dev_max_mm` ($t_c$ ~ `t_end` 최댓값) · `stop_exec_along_end_mm` (직선 방향 위치, 공의 진행 방향이 +). 계획: `stop_plan_dev_end_mm` · `stop_plan_dev_max_mm` · `stop_plan_along_end_mm` (그 구간의 풀이가 자기 해에 대해 적은 값 — 그 구간의 노드만이라 최댓값의 구간이 실행과 같지 않다). commit 이 없거나, 창 안에서 held 가 서지 않거나, 창이 `t_end` 전에 끝나거나, `segment_held` 열이 없으면 전부 NaN. 실행의 세 열은 `t_c` 열에서 읽으므로 `tc_axis` 가 `shifted` 인 행을 중앙값에서 뺀다. 계획의 세 열은 풀이의 기록이라 모든 유효 시행을 쓴다.
- **닫는 창의 경로 이탈 (`win_*`)**: 손이 닫히는 동안 측정 catch frame 이 공의 경로에서 얼마나 떨어져 있었는가. 닫기 명령 시각은 이름뿐인 $t_c - T_{close,lead}$ 가 아니라 **로그에서 읽는다** (시퀀서가 commit 뒤 재조정할 수 있다): diag `hand_phase` 가 `CLOSE`(2) 로 들어서는 tick 중 $t_c$ 에 가장 가까운 것. `win_t_cmd_ms` 는 그 시각 − $t_c$. 창은 $[t_{cmd}, t_{cmd} + T_{close,e2e}]$ (runner 미러 `hand.T_close_e2e`, 없으면 프로파일의 `robot.hand.T_close_e2e`; 요약의 `t_close_e2e_s` · `t_close_e2e_source` 가 값과 출처), `win_exec_dev_max_mm` · `win_exec_dev_end_mm` 은 창 안 측정 FK 가 공의 자유비행 **경로** (1 ms 로 표본한 곡선, 창 ± 0.3 s; 선분까지의 최단 거리이므로 경로를 따른 시간 오차는 벌하지 않는다) 에서 떨어진 거리의 최댓값 · 마지막 tick 값이다. truth · commit · 닫기 명령 · $T_{close,e2e}$ 가 없거나 창이 기록보다 길면 NaN. 기준이 명령 tick 이므로 `shifted` 행도 중앙값에서 빼지 않는다.
- **그 wake 의 예측과 계획 (`pred_wake_*` · `plan_wake_*`, `--probe-dump`)**: `cf_ref_*` 를 둘로 가른다 — $p_{true}(t_c) - \mathrm{ref} = [p_{true} - \hat p_{wake}(t_c)]$ (예측: 추정기 몫) $+ [\hat p_{wake}(t_c) - \mathrm{ref}]$ (계획: 풀이 몫), 같은 catch frame 의 `{x,y,s}_mm`. $\hat p_{wake}$ 는 `last_seg_snapshot_seq` · `_gen` 의 snapshot 을 공 stamp 축의 $t_c$ 에서 읽은 것이다 (가장 가까운 지평 점의 $v$ · $a$ 로 전개, `catching_vision.state_hat_at`). `pred_wake_lat_mm` (예측 몫의 lateral 길이), `plan_wake_lateral_margin_mm` (**풀이가 본** 공의 lateral margin — docking 풀이는 공을 $s = s_{ent}$ 에 집합 안에 두므로 `plan_wake_s_mm` 이 $s_{ent}$ 이고 이 margin 이 양수인 것이 결합 자체의 검사다), `pred_wake_v_perp_m_s` · `pred_wake_v_s_m_s` (속도 오차 $v_{true} - \hat v$), `pred_wake_horizon_ms`, `pred_wake_join` (`exact` / `missing` = 키는 아는데 probe 가 받지 못함 / 빈 값 = 키 없음).

**D-3 공변량**. `clock_phase` 를 재사용해 $\delta_{max}$ · max pause · $\delta(t_{commit})$ · $\delta(t_c)$, `--eps-mm` 별 유효 수를 낸다. lane 의 발사는 순서가 아니라 하나의 시계 오프셋으로 시행과 짝짓는다: 한 세션에 러너를 두 번 돌리거나 GUI 로 던진 발사가 섞여도 그 발사는 무시되고 짝 없는 시행은 `unpaired_trials` 로 남는다 (절반 미만이 짝지어지면 다른 run 으로 보고 거부). `--v-max` 는 기본값이 없다 (목표 분포의 최대 포구 속력, 로봇 상수라 CLI 로 받는다). 없으면 `NOT_EVALUATED(v_max not given)`.

**RTF 공변량**. `rtf_flight` (발사 ~ 첫 접촉 또는 sim 0.6 s 의 sim 구간 / steady 구간) · `rtf_trial_min` (시행 끝까지 sim 0.25 s 창 중 최솟값), 요약 `rtf` p05/p50/min. 무효 규칙이 아니다.

**tick overrun 공변량**. `<session>/timing/cm_timing_log.csv` (RT 루프 tick 당 한 행) 에서 시행 창 안 `t_total_us` > 제어 주기인 tick 수 (`tick_overrun_n`) 와 최대 `jitter_us` (`tick_jitter_max_us`), 요약 p50/p95/max. `t_wall_ns` 는 이름과 달리 steady_clock 이라 러너의 `launch_wall_time` (epoch) 과 기준이 다르다 — clock lane 으로 잇는다. lane 이 없으면 `NOT_EVALUATED(no clock lane …)`, 파일이 없으면 `NOT_EVALUATED(no timing log)`. sim 모드 CM 은 `jitter_us` 를 0 으로 낸다.

**G8-B (`--eval-samples`)**. `sim_capture_evaluate` 의 `eval_samples.csv` 중 prediction 행을 시행에 묶는다: 시각 `time_ns` ≥ 발사 stamp 이고 **목표 시각 `time_ns + horizon_ns` ≤ 첫 접촉** (`t_first_impact`, 없으면 마지막 truth stamp) 인 것만. 그 뒤 표본은 손 안의 · 리셋된 공과 비교한 값이라 예측을 말하지 않는다. 행 열 지평별 `nees_h<h>ms_{n,nan,mean,cov95}` · `err_h<h>ms_{x,y,z}`. 요약 `g8b` 는 지평별 합산 평균 NEES ($\Sigma\,\mathrm{NEES} / \Sigma\,n$, 시행 평균의 평균이 아님) · 시행 부트스트랩 95 % CI · CI ∋ 3 이면 PASS · NaN > 10 % 이면 `NOT_EVALUATED(NaN > 10 %)` · coverage_95 ($\chi^2_3$ 0.95 = 7.815 이하 비율) · 부호 있는 편향이다. `--eval-report` 는 `eval_report.json` 의 지평별 수치를 `g8b_unrestricted` 로 판정 없이 옮긴다 (접촉 후 truth 포함).

**G8-C2 (`--probe-dump`)**. commit tick 마다 $A = p_{true}(t_c) - \hat p_{live}(t_c)$, $B = \hat p_{live}(t_c) - p_c$ (sim world; $p_c$ 는 truth 와 같은 `world_t_model` 로 옮기며 계획 snapshot 의 점과 µm 단위로 일치하는 것이 프레임 검사다). $t_c$ 는 계획 snapshot 에서 $p_c$ 인 점의 stamp + horizon (`c2_tc_source: plan_point`; 없으면 계획 steady $t_c$ + realtime − steady, 그다음 `t_c` 열). `c2_tc_minus_tc_ms` 가 `t_c` 열과의 차다. $\hat p_{live}$ 는 commit tick 의 diag `input_snapshot_sequence` · `input_generation` 을 dump 의 `snapshot_sequence` · `generation` 에 정확 결합 (`c2_join: exact`), 없으면 commit tick 의 steady 시각 이전에 probe 가 마지막으로 받은 snapshot (`approx`) 이고 점 사이는 가장 가까운 지평 점의 $v$ · $a$ 로 전개한다. 요약 `c2`: $n$ · exact/approx 수 · $|A|$/$|B|$ 중앙값 · $E|A+B|^2$ 대 $E|A|^2+E|B|^2$ 와 교차항 $2E[A\cdot B]$ · `independence_test` ($n$ < 100 이면 `NOT_EVALUATED(n < 100)`).

**손-관절 캡처 witness**. diag 의 `hand_stalled_n` / `hand_effort_frac` / `hand_blocked_s` (연속 불통 지속 시간 [s], 0 = 안 걸림) / `outcome_source` (열이 없는 구 세션은 NaN) 에서 시행당 `outcome_source` (0 none · 1 fingertip · 2 hand · 3 both) 를 읽는다.
- HOLD 끝 tick 에 판정되지만 그 tick 은 이미 mode RETREAT 로 기록되므로 `outcome_source` 는 **첫 RETREAT 행**에서, `hand_blocked_s_judge` · `hand_stalled_n_judge` · `hand_effort_frac_judge` (판정이 참조한 손 스테이지 값) 는 그 한 tick 전인 **마지막 HOLD 행**에서 읽는다. RETREAT 가 ABORT_SAFE 등에서 들어왔으면 전부 NaN.
- `tips_only_verdict` 는 손 witness 없이 손끝만 있었다면의 재구성이다 (`CAPTURED` + `outcome_source == 2` → `MISSED`, 그 외 그대로). `t_release_to_pre_ms` 는 release tick 부터 손이 `q_pre` 로 돌아온 첫 PRESHAPE tick 까지다.
- **`hand_blocked_s_judge` 는 판정이 비교한 값보다 정확히 한 tick 짧다**: 컨트롤러의 `JudgeOutcome` 은 그 다음 tick (첫 RETREAT tick) 에서 `t_persist` 와 비교하므로 오프라인 재현은 `hand_blocked_s_judge + dt >= t_persist` 를 써야 한다. `hand_persist_met` 열 (1.0/0.0/NaN) 이 그 재현이고 `t_persist_s` 는 `catching.robot.hand.capture.t_persist` 에서 읽는다 (TBD · 없음이면 NaN).
- $\rho_{min}$ / $\rho_{max}$ / `qd_tol` / `effort_frac_min` 캘리브레이션: `hand_hold_window_extremes` 가 매 시행의 `[t_hold_end − --hold-window-s, t_hold_end)` 구간에서 caging 관절별 극값 (`rho_lo` / `rho_hi` / `qd_absmax` / `frac_lo` = $s\tau/\tau_{max}$ 최솟값 / `n`) 을 내고, HOLD 끝에서 RETREAT 로 들어간 시행 (ABORT_SAFE 경유 제외) 에 한해 `hand_hold_window.csv` (long-format, `idx,joint,supervisor,rho_lo,rho_hi,qd_absmax,frac_lo,n`) 에 쓴다. `--hold-window-s` 기본값 0.1 의 SSoT 는 `Settings.hold_window_s` 다. `capture_would_fire` 는 그 극값이 임계를 (경계 포함) 만족하는 관절이 `min_joints` 개 이상인지로 `EvaluateHandCapture` (hand_capture.hpp) 의 오프라인 미러다. 캘리브레이션은 선택 사항이라 입력이 빠져도 (`q_pre`/`q_close` TBD, `caging_mask` 길이 불일치, `joint_limits.max_torque` 없음, 손 CSV 에 `actual_vel_*`/`effort_*` 없음) 세션 분석은 계속된다. `q_pre`/`q_close` 길이가 서로 다르거나 비면 같은 YAML 블록의 모순이라 `SystemExit`.

### planner_solves

`planner_events.csv` 의 풀이 시간 (`segment_solve_us`) 을 읽는 규칙 하나와 그 위의 표다. `plot_rtc_log` 통계, `catching_trials` 의 `first_solve_cut`, `integrated_bringup/tools/catching_eval/unit_report.py` 가 부른다.

### catching_pool

arm 마다 여러 unit (sim 세션 + trials dir) 을 합쳐 판정한다. 입력은 unit 마다 `catching_trials` 를 돌린 출력 dir 이다. 옛 도구의 출력 (`decel_*` 이름의 열 · 요약 키) 은 읽지 않고 다시 만들라는 오류로 멈춘다. `invalid_reason` 열이 없는 CSV 도 거부한다.
- **보충 절단** (D-S8-16 ①b): CT_DIR 은 준 순서대로 (사전 선언 seed 순, 보충 unit 은 마지막) 읽고 시행은 `idx` 순이다. 누적 유효 수가 `--n-valid-target` (기본 200) 에 닿는 시행까지 포함하고 그 뒤는 `beyond_target` 으로 유효 · ITT 양쪽에서 뺀다 (수는 보고). 전부 합쳐도 모자라면 `INSUFFICIENT_N`.
- **arm 별**: `n_total` · 사유별 무효 · `n_valid` · 성공 · $\hat p$ · Wilson 95 % · `lower_975` · `--floor` 판정 · ITT · 슈퍼바이저 × truth 혼동행렬 · unit 별 표. 같은 모집단의 D-3, tick overrun, G8-C3 분포, G7-B3 (세션과 같은 함수로 합산 시행에서 다시 계산), `map_open` 이 있으면 gate-map 전체 / 지도-열림 부분집합. `--z` (기본 1.96) 는 Wilson $z$.
- **McNemar** (arm 2 개 이상): 두 arm 에서 모두 포함 · 유효인 `(seed, idx)` 쌍만으로 A 성공 ∧ B 실패 ($b$) · A 실패 ∧ B 성공 ($c$) · 정확 이항 양측 $p$ (`scipy.stats.binomtest`). seed 없는 유효 행 수는 따로 적는다. 한 arm 에 같은 `(seed, idx)` 가 두 번 나오면 (원본 unit 과 재실행 unit 을 둘 다 준 경우) 거부한다.
- **D-3 S3.1b** (D-S8-16 ⑤): arm 들의 clock 공변량 시행 수 (포함 · 유효 · 유한 `delta_max_ms`) 만으로 ≥ 200 (`met`) 을 판정한다. `--extra-d3` 요약 JSON 의 `d3.paired` 는 모집단이 달라 (그 요약의 lane 발사가 있는 accepted 시행 전부) 옆에 나열만 하고 더하지 않는다. 요약 JSON 의 분위수도 합칠 수 없으므로 출처별로 적는다.
- **G8-B · G8-C2 · RTF · 시각 정렬**: 합산 시행의 행 열에서 다시 계산한다 (G8-B 는 시행별 합 · 수로 정확한 합산 평균과 시행 부트스트랩, G8-C2 는 시행당 $(A, B)$ 하나라 표본 = 시행 클러스터, $n \ge 100$ 이면 `independence_test`). unit 별 `time_alignment` 를 옮겨 적는다.

### catching_hand_near

`catching_sim_trials --dist hand_*` 로 던진 unit (손 반경 ≤ 0.2 m 로 오는 공을 얼마나 빠르게까지 받는가, S8-F) 을 읽어 **plan 이 있었는가 (COMMIT)** 와 **plan 이 있을 때 잡았는가 (CATCH)** 를 따로 적합한다. 성공 하나로 뭉치면 "못 도달" 과 "도달했는데 놓침" 이 섞여 시간 내 도달 > 상대속도의 우선순위에 답하지 못한다. unit 은 `<unit>/trials` + `<unit>/ct` 이고 선택으로 세션의 `planner_events.csv` 를 `<unit>:<csv>` 로 붙인다.
- **조준 검증**: 시행마다 러너가 남긴 `aim_error_m` 의 최대 · p50 과 `--aim-tol-mm` (기본 2) 초과 시행 목록, `model_rms_m` (첫 접촉 전 truth 대 모델) 의 최대 · 초과 목록. `aim_error_m` 은 조준에 쓴 공 파라미터로 다시 적분한 값이라 항력 법칙이 틀려도 0 이므로 (beanbag unit 을 tennis $C_d$ 로 돌린 경우) 두 번째가 그것을 잡는다. 어느 쪽이든 하나라도 넘으면 rc 1 — 던진 곳이 설계와 다르다. `aim_error_m` 이 한 시행에도 없으면 `pass: null` ("no data") 이고 rc 1.
- **grid arm** (`hand_cliff` · `hand_lob`): 속력별 $n$ · commit · catch 와 Wilson 95 % (catch · plan · catch | plan) 표, 속력 하나에 대한 로지스틱의 $v_{50}$ + 시행 부트스트랩 CI (`--n-boot`, 기본 500; 유한 복제 20 미만이면 NaN).
- **LHS arm** (`hand_lhs`): 설계 인자 $[1, v, r, r^2, T-0.7, \alpha, v r, \sin\psi, \cos\psi]$ 의 로지스틱 GLM (numpy IRLS, 기울기에 1e-4 ridge — 절벽은 완전 분리라 ridge 없이 발산) 을 commit · catch | commit · 전체 성공 셋에 적합한다. $r \in \{0, 0.05, 0.1, 0.15, 0.2\}$ 에서 설계 중심 ($T$ 0.7 · 정면 · $\psi$ 평균) 의 $v_{50}(r)$ 과 두 단계 곱 $P(\text{plan})P(\text{catch}|\text{plan}) = 0.5$ 의 $v_{50}$ 을 부트스트랩 CI 와 함께 `v50_map.csv` 로 낸다. ($r$ 구간 × $v$ 구간) pooled Wilson (`wilson_cells.csv`) 이 모델 없는 검산이다. 도달량 (Δz · 입사각) 은 $(v, T, \alpha)$ 의 도출량이라 GLM 에 넣지 않는다.
- **$v_{rel}$**: commit 된 시행의 **측정** 접촉 상대속도 (`contact_v_rel`) 하나에 대한 로지스틱 → `v_rel50` (L6 §4.5 fly-in 허용량의 폐루프 대응값).
- **A/B** (`--ab A B`): 두 arm 라벨 (`run_meta.json` 의 `arm`) 을 `(kind, seed, sample_idx)` 로 짝지어 (설계마다 `sample_idx` 가 0 부터라 `kind` 없이는 같은 seed 의 cliff 와 lhs 가 겹친다) catch 와 commit 각각 McNemar 정확 검정. 짝 없는 시행 수는 따로 적는다.
- **planner_events**: 게시된 plan 중 `rank_reach` · `rank_gamma` 순위 gate 에 걸린 비율과 판정 거부 수 (`rej_ik` · `rej_too_far` 등). `rej_workspace` 는 탐색에 `catch_box` 가 있던 세션에만 있는 열이고 (L3 §4.9) 그 뒤의 세션에서는 0 으로 읽힌다.

### catching_arm_budget

"팔이 못 간다" 를 네 층 — **P** 플랜트 (서보 지연 $\tau$ · 토크 여유 · 도달 속도) · **R** L4 참조 ($\omega$ 수렴, `a_max` / `v_max` 포화) · **C** CLIK (속도 box = device 정격, 가속 제약) · **B** 계획기 (도달시간이 판정하는 D-16 box, 결정 K 이후 CLIK 이 실행하는 것과 다르다) — 중 어디가 묶였는지를 unit 하나와 그 컨트롤러 세션에서 시행 · unit 단위로 나눈다. `<unit>[:<session>]` (세션 기본 `<unit>/session_copy`).
- **잔여 분해**: 참조 자기 오차 ‖e‖ 를 commit 과 마지막 활성 tick ($t_c - T_{arm}$, 그 명령이 $t_c$ 를 겨냥한다) 에서 읽어 `catching_trials` 의 `ref_vs_true` · hand–ball · `d_min` 옆에 놓는다 — 차이가 예측 몫 (하한 `pred_live_lb`). 임계감쇠 2차 참조의 이론 잔여 $(1+\omega T)e^{-\omega T}$ 를 함께 찍어 $\omega T$ 의 산술을 포화 · 추종과 구별한다.
- **R**: ‖u_des‖ (포화 전 요구 가속) p50/max, `a_max` 적중 · `ref_saturated` 비율, ‖ẋ‖ max 와 $\eta_v v_{max}$ 적중.
- **C**: 실행된 관절 가속 **envelope** (활성 tick 의 5-tick 평균 $|\ddot q_{cmd}|$ p95 / max), 속도 box (정격, `_base.yaml` 위에 `sim.yaml` 의 같은 키) 적중 비율, 계획기 box 초과 tick 비율.
- **P**: $\hat\tau$ 관절별 (`catching_trials.servo_lag_ls`), device lane `effort_*` 의 토크 사용률 max/p99 (lane 없으면 NaN), 도달한 관절 속도.
- **B**: 같은 운동 (commit → 마지막 활성 tick 의 $\Delta q$, 초기 속도 포함) 의 도달시간을 컨트롤러가 로드한 D-16 box 와 실행 envelope 로 **두 번** 재 (L3 §4.3 닫힌해 이식) commit 시점 가용 lead 와 비교한다 — box 의 비관이 숫자가 된다. `planner_events.csv` 의 유효 plan 중 rank gate 실패율도 함께 낸다.
- **한계의 출처** (ARCH-1): 관절은 diag `q_cmd_*`, 토크 · 속도 정격은 프로파일 device 명세, $\omega$ / `a_max` / `v_max` / $\eta_v$ / `planner.search.grid.time.margin` / box 는 러너가 `run_meta.json` 에 남긴 컨트롤러 **미러** (TBD 잎도 컨트롤러가 실행한 기본값으로 낸다). 없으면 컨트롤러 YAML → `sim.yaml` 의 `<controller>.catching` override → `--overlay` 순으로 합성하고 출처를 `budget.source` 로 보고한다. `--time-margin-s` 는 그 해소값을 덮는 명시 override 다.
- `--write-envelope-box`: unit 들의 envelope p95 를 관절별 max 로 모아 sim override 조각 (`<controller>.catching.robot.arm.qdd_max` 와 `qdd_provisional: true`) 으로 쓴다. 로봇 config 의 `sim.yaml` 에 옮기거나 `--overlay` 로 넘긴다. 토크 도출이 아니라 실행값이므로 sim 전용이다.

### catching_decel

포구 뒤 팔을 세우는 방식 (v1 의 closed-form 가상 목표, MPC 궤적의 꼬리) 을 같은 잣대로 잰다. 입력은 unit (`catching_sim_trials` 출력 + `<unit>/ct`) 과 컨트롤러 세션이고, 포구 diag 의 `mode` · `q_cmd_*` · `q_meas_*` · `ref_xd_*` 와 팔 device lane 의 `effort_*` 를 읽는다. `<unit>[:<session>]` (세션 기본 `<unit>/session`, 없으면 `<unit>/session_copy`).
- **창은 mode 가 아니라 손의 task pose 가 정한다**: 시행의 첫 `DECEL` tick 부터 측정 catch frame 이 task pose 에서 정지한 첫 tick 까지. 정지는 선속도가 `--rest-speed` (기본 0.02 m/s) 아래이고 접근축 (catch frame +z) 각속도가 `--rest-axis-rate` (0.2 rad/s) 아래인 상태가 `--rest-s` (0.05 s) 동안 이어지는 첫 구간의 첫 tick 이다. 첫 `RETREAT` tick 을 넘지 않고, 그 전에 멈추지 못하면 `rest_reached = false`. v1 은 가상 목표가 멈추는 tick 에 `DECEL` 을 떠나지만 팔은 서보 지연만큼 더 움직이므로 mode 길이 (`mode_decel_s`) 는 참고값이다.
- **관절이 아니라 task pose 인 이유**: 포구 컨트롤러는 manipulability 를 올리는 null-space 운동을 더하므로 task pose 가 멈춘 뒤에도 관절은 움직인다. 관절 속도로 판정하면 정지가 아니라 `HOLD` 의 길이를 읽는다. task 는 catch frame 의 위치와 접근축이고 접근축 둘레의 roll 은 null space 라 판정에 넣지 않는다. 참고값으로 관절 기준 (`joint_rest_reached`, `--joint-rest-speed`) 과 roll 포함 frame 각속도 (`angular_speed_*`) 를 병기한다.
- **가속 · jerk 피크**: 창 안 관절 · tick 최댓값, 명령과 측정 각각. tick 격자의 `np.gradient` 를 `--smooth-ticks` (기본 5) box 평균한다. v1 의 기준 가속은 진입과 정지에서 계단이라 평활하지 않은 jerk 는 tick 길이의 함수다 — `jerk_cmd_raw_peak` 는 참고값. 미분은 창 앞뒤 25 tick 을 붙여 구한 뒤 자른다.
- **정지 거리 · 시간**: 측정 catch frame 의 변위와 경로 길이, $t(k_1) - t(k_0)$. 닫힌식 $\|\dot x_s\|^2/(2 a_{dec})$ (진입 tick 의 `ref_xd`, `supervisor.decel.a_dec`) 는 참고값이며 diag 에 `ref_xd_*` 가 없으면 NaN.
- **한계 여유**: 위치 한계까지의 최소 거리, $|\dot q_{meas}|/\dot q_{max}$ · $|\text{effort}|/\tau_{max}$ 의 최댓값. 위반은 여유 < 0 또는 비 > 1 인 시행 수다. 정격은 `catching_arm_budget._device_limits` 와 같은 합성이고 `a_dec` 는 컨트롤러 YAML → `sim.yaml` → `--overlay` 순이다. 넷 중 하나라도 없으면 거부한다.
- **요약**: 시행별 값의 p50/p95/max 를 unit · 합산, 전체와 truth 성공 · 실패로 나눠 낸다. `DECEL` 에 들어가지 않은 시행은 지표에서 빠지고 성공률 분모에는 남는다 (abort 는 실패). 한 시행의 두 번째 `DECEL` 구간은 세지 않는다. 합산 블록은 한 arm 의 것이다: `pooled` 는 위치 인자 unit 만 합치고, `--a`/`--b` 는 `pooled_a` · `pooled_b` 를 내며 둘을 합친 `pooled` 는 `--same-arm` (같은 arm 의 복제) 일 때만 낸다.
- **`--a` / `--b`**: `(kind, seed, sample_idx)` 로 짝지은 truth 성공의 2×2 표, 불일치율 $\psi$ 와 Wilson 구간, McNemar 정확 검정, paired 단측 비열등 검정이 요구하는 쌍 수 $(z_\alpha + z_\beta)^2(\psi - d^2)/(\delta + d)^2$ 를 `--margin` 마다 $\hat\psi$ 와 $\psi$ 상한에서 낸다 (설계는 [mpc_multiframe_clik_formulation](mpc_multiframe_clik_formulation.md) §6.5). 공통 throw 가 없거나 불일치 쌍이 하나도 없으면 쌍 수는 `null` 이다 (0 은 "쌍이 필요 없다" 로 읽힌다).
- **성공 정의 `--success`**: `truth` (기본, `truth_success`) 또는 `hold` = `truth_success` 이고 `catching_trials.csv` 의 `hold_verdict` 이고 `abort_in_window` 가 아닌 것. 두 열은 `catching_trials` 가 truth 열과 같은 시행 창에서 내므로 한 시행의 판정은 창 하나에 선다. 시행마다 `hold_no_abort`, 단위 · pooled 블록마다 `hold_success`. 두 열이 없는 옛 평가에 `hold` 를 주면 거부한다.
- **비열등 검정** (게이트 G-1): `pairs.noninferiority` 에 `--margin` 마다 Tango (1998) score 검정 $H_0: p_b - p_a \le -\text{margin}$ — $Z = (x_b - x_a - n\delta_0)/\sqrt{n[2\tilde q_a + \delta_0(1-\delta_0)]}$, $\tilde q_a$ 는 경계의 제한 MLE (2 차식의 큰 근), $p = 1 - \Phi(Z)$, 비열등 ⇔ $p$ < `--alpha` (단측). score 구간은 $1 - 2\,$`--alpha` 수준이라 그 하한이 $-$margin 을 넘는 것이 곧 기각이다. $\hat d$ 와 같은 수준의 Wald 구간 (`paired_difference`, `catching_grid_sweep` 도 사용) 은 margin 과 무관해 `pairs.wald` 에 한 번만 낸다. 검정력은 삼항 분포를 전부 열거한 정확값이다: `--design-psi` 를 주면 그 $\psi$ 와 `--design-n` (계획한 쌍 수, 없으면 유효 쌍 수) 에서, 그리고 관측 $\hat\psi$ 와 유효 쌍 수에서 `--power-diff` (기본 0 · −0.05) 의 참 차이마다 낸다 ($|d| > \psi$ 인 칸은 `null`). `size` 는 $\hat\psi$ 의 $H_0$ 경계에서의 정확 기각률이다. `--alpha` 는 (0, 0.5), `--design-psi` 는 [0, 1], `--design-n` 은 1 이상이어야 하며 어긋나면 unit 을 읽기 전에 거부한다. scipy 를 쓰지 않는다.

### catching_grid_sweep

vision 예측 격자 (horizon × 점 수) 를 조건마다 바꾸고 같은 투척 (같은 seed) 을 던진 unit 들을 조건 = arm 으로 묶어 비교한다. unit 은 `catching_decel` 과 같다. 로봇마다 따로 돌린다.
- **조건은 unit 이 말한다**: 러너가 `run_meta.json` 에 남긴 컨트롤러 미러의 `prediction.dt_expected` · `io.n_min` · `planner.search.grid.slice.dt` 를 arm 마다 옮겨 적고 한 arm 의 unit 끼리 다르면 거부한다. 미러에 세 키가 없는 unit 은 격자를 모르므로 거부하며, `--allow-unknown-grid` 를 주면 `grid_known: false` 로 받는다. 받은 점 수는 diag 에서 새 snapshot 을 받은 tick 의 `input_n` 최빈값이다 (점 0 개 snapshot 은 세지 않는다). 도구는 조건 이름도 로봇 상수도 모른다 (ARCH-1).
- **메시지**: 크기는 `point_step` 384 B × 점 수 (컨트롤러 decoder 가 다른 `point_step` 을 거부하므로, header 제외). 주기는 새 snapshot 사이 간격이며 `--flight-gap-s` (기본 0.5 s) 보다 긴 간격은 비행 사이라 뺀다. 축은 diag 의 `t_relative_s` 이고 추정기의 발행 주기가 아니라 **컨트롤러가 받은** 주기다.
- **오차**: `pred_mm` · `total_mm` 은 `tc_axis` 가 `shifted` 인 시행을 빼고, `contact_v_rel` 과 `approach_plan_switches` 분포는 유효 시행 전부를 쓴다. `rtf_trial_min` < `--rtf-min` (0.95) 인 시행 수와 값이 없는 시행 수 (`rtf_unknown`, 모르는 것은 통과가 아니다) 를 세기만 한다 (unit 재실행 판정은 수집 규칙의 몫).
- **계획기**: `planner_events.csv` 중 창 안에 후보가 있던 주기 (`n_in_window` > 0) 의 `search_us` p50 / p99 / max, `budget_hit`, 후보 · IK 수의 최대. `--budget-s` 를 주면 p99 가 그 값을 넘는 arm 을 표시한다. 컨트롤러가 이 파일을 best-effort 로 열므로 파일이 없는 unit 은 거부하지 않고 `planner_events_missing` 으로 센다.
- **비교**: `(kind, seed, sample_idx)` 로 짝지은 2×2, paired 차이 $p_B - p_A$ 와 Wald 95 % 구간 ($((b+c) - (c-b)^2/n)/n^2$), McNemar 정확 $p$, family 안의 Holm 보정 $p$. `--ref` 대비 비교가 한 family, `--pair` 가 다른 family 다.

### catching_capture_set

`mpc_docking` (참고: [ball_catching_inverse_dynamics_mpc](ball_catching_inverse_dynamics_mpc.md) §6 · §8.4 · §17.6–§17.8) 이 받는 손 · 포획 쪽 값 — 통과 평면 $s_{ent}$, lateral 집합 $\mathcal C_\perp$, 속도 집합 $\mathcal V_{cap}$, 폐쇄 창 — 을 fly-in 판정에서 계산하는 **순수 함수**다. CLI 가 없고 simulator · ROS · 로봇 이름을 모른다. 판정을 만드는 rig 와 드라이버는 `integrated_bringup/tools/docking_ident/` 에 있다.
- **판정은 격자의 셀에 속한다.** 셀의 시행 전부가 유지돼야 그 셀이 유지다 (`held_cells`). 그래서 이 모듈이 내는 구간의 끝은 모두 셀의 가장자리다.
- **상자** (`held_boxes` · `box_by_min_width`): (closing speed, 폐쇄 시각) 지도에서 전부 유지된 직사각형. 후보는 폐쇄 시각의 폭이 요청한 값 이상인 것 가운데 closing speed 상한이 가장 큰 것, 같으면 면적이 큰 것이다.
- **폐쇄 시각의 축이 둘이다.** 유지 여부는 공이 **원점**에 닿는 시각 기준 ($\delta^O$) 이고 코어의 창은 $s = s_{ent}$ **통과** 기준 ($\delta = \delta^O + s_{ent}/c$) 이다. 코어는 허용하는 모든 속도에 창 하나를 쓰므로 상자에서 얻는 창은 $s_{ent}(1/c_{lo} - 1/c_{hi})$ 만큼 좁다 (`entrance_window`). 빈 창도 그대로 돌려준다. `entrance_rows` 는 $c_{hi}$ 를 두고 $c_{lo}$ 를 올린 부분 구간마다의 창을 낸다.
- **lateral 다각형** (`inscribed_circle` · `capture_polygon`): 유지된 셀 안의 가장 큰 격자점 중심 원에서 시작해 방향이 고정된 8 면을 한 칸씩 밀어 넓힌 볼록 다각형이다. 단위 법선 · 공 중심 좌표 (코어의 `face_a` · `face_b`). 재지 않은 곳은 유지가 아니다.
- **통과 평면** (`Occupancy` · `approach_table` · `ApproachTable.entrance`): preshape 손의 정적 접촉 격자에서 lateral 집합의 모든 점을 지나는 모든 기울기의 직선이 그 위로 무접촉인 가장 낮은 높이. 위에서 내리며 처음 막히는 높이에서 멈춘다. 격자 사이의 위치는 둘러싼 열 가운데 하나라도 닿으면 닿는 것으로 하고, lateral 격자를 벗어난 직선은 닿은 것으로 세되 `scan_limited` 로 표시한다. `corridor_fit` 은 같은 격자에서 축 둘레의 무접촉 원뿔 (`r_ent` · `tan_theta`) 을 낸다.
- **옆 속도의 상한** (`rings_within_drop` · `largest_held_radius`): 속도 고리의 유지율을 옆 속도가 없는 기준 고리의 유지율과 견주어, 허용한 폭보다 더 낮지 않으면 통과다. 통과가 이어지는 마지막 고리의 바깥 가장자리가 상한이다. 시행 하나의 판정이 집합 안에서도 확실하지 않아 "고리의 시행 전부가 유지" 로는 기준 고리 자신도 통과하지 못한다.
- **검증**: `sample_capture_set` (식별한 집합에서 균등 추출) 과 `clopper_pearson_lower` (유지율의 단측 정확 하한).

### catching_wait_pose_search

`catch_speed_budget` 이 **수락된** 포구 자세의 속력 예산을 답한다면, 이 도구는 공이 보이기도 전에 팔이 서 있는 **대기 자세** (`planner.wait_pose`, IK seed) 를 바꾸면 그 자세가 낼 수 있는 방향 속력 상한이 얼마나 오르는가를 답한다. 목적함수는 **자기 자신의 접근축 기준**이다: $\hat v(q) = -\mathrm{axis}(q)$ (axis = catch frame +z, model world). 고정된 풀링 방향이 아닌 이유는 손-근처 투척 (S8-F) 생성기 (`catchability_map.aim_at_hand`) 가 각 공을 미러링된 대기 자세 자신의 palm normal 로 조준하기 때문이다.
- **목적** `--objective`: 기본 `dls` = `directional_speed_dls` (런타임 `DirectionalSpeedMax` 가 $\gamma$ 창에 넣는 값 — 최대화하면 계획기 자신의 $\gamma_{max}$ 가 최대), `lp` = `directional_speed_lp` (LP 물리 상한), `robust`. 두 값은 행마다 같이 내고 DLS 는 LP 를 넘지 않는다. 탐색은 LP 의 **값만** `directional_speed_lp_value` 로 구한다 (5 행 $[J_p; J_w]$ 가 full rank 이고 여유 관절이 1 개 이하면 영공간 1 차원 위의 구간선형 최소화로 정확히 풀고, 그 밖은 LP 로 넘긴다).
- **`robust`**: 한 점의 정적 DLS 최대값은 $j_w$ 특이점 옆의 바늘 봉우리가 되기 쉽고 계획기가 실제로 가는 IK 포구 자세는 거기서 떨어져 속력이 훨씬 낮다. 그래서 이 목적은 **이웃**의 값이다: `--robust-samples` 개 (기본 32) 의 관절 섭동 $|\delta|_\infty \le$ `--robust-eps-rad` (기본 0.1) 에 대해 명목 자세의 접근축 방향 DLS 를 재고 그 p10 을 명목 LP 로 cap 한 값 (`v_dir_robust`). 섭동 집합은 탐색당 한 번 뽑아 (common random numbers) 모든 후보를 같은 오프셋으로 채점한다. 행마다 `sigma_min` (DLS 가 역산하는 5 행 $[J_p; J_w]$ 의 최소 특이값, 단위가 섞인 조건수 지표) 도 내고 `--min-sigma` 가 제약이 된다. IK 수락 · 충돌은 보지 않는다.
- **한계의 출처** (ARCH-1): 관절은 `devices.<arm>.joint_state_names`, **탐색 관절 상자는 런타임이 대기 자세를 받아 주는 상자** (`joint_limits.position_lower/upper` 를 `catching.robot.arm.limit_margin` 만큼 안으로 당기고 URDF 한계와 교집합; 위치 한계가 없으면 URDF), 속도 box 는 `catching_arm_budget._device_limits` 와 같은 합성, $\eta_v$ · `planner.wait_pose` 는 catching 컨트롤러 YAML 이다.
- **탐색**: joint-limit box 균등 표본 + 대기 자세에서의 log-scale 랜덤워크를 `--radius-m` ($\|p - p_{ref}\| \le r$) · `--axis-tol-deg` (참조축과의 각) · `--box` (위치 상자) · `--min-z` 로 거르고, 자기 일치 LP 로 순위를 매겨 상위 `--refine-top` 개를 제약 위반 벌점을 준 Nelder–Mead 로 정련한다. 정련은 벌점(soft)만 걸므로 국소해가 하드 제약을 벗어나면 제약을 만족하는 raw 표본으로 되돌린다 — 보고되는 모든 행이 제약을 어기지 않는 것은 이 fallback 의 보장이다.
- **출력**: `wait_pose_candidates.csv` (참조 행 + raw/refined 상위; rank · stage · 관절별 `q_<joint>` · p · axis · `v_dir_lp` · `v_dir_dls` · `v_dir_robust` (robust 목적일 때 모든 행, 아니면 참조 행만; 나머지 NaN) · `sigma_min` · `max_dq_rad` · `dist_m` · `axis_deg` · `in_box` · `within_limits`; 참조 행은 `--box` 를 만족하지 않아도 비교 기준으로 실린다) 와 `wait_pose_search_summary.yaml` (provenance: config 파일 · $\eta_v$ · $\dot q_{max}$ 와 출처 · 참조 자세와 그 자신의 `v_dir_lp/dls` · elevation · 제약 · 샘플링 · 최선 정련 자세 + `overlay_snippet`).
- **자체 검증 (fail-closed)**: 보고되는 모든 행이 FK($q$) 로 재계산한 위치가 보고값과 1e-9 m 이내로 일치하고, URDF 관절 한계 안이며, `v_dir_dls` 가 그 행의 `v_dir_lp` 를 허용치 (상대 1e-3 + 1e-6 m/s) 넘게 초과하지 않아야 하고 (탐색 중 그런 후보는 "DLS 아티팩트" 로 버린다), `v_dir_robust` 도 LP 를 넘지 않아야 한다. 하나라도 어기면 아무것도 쓰지 않고 종료한다.
- **LP 의 의미**: 접근축 회전 속도를 0 으로 고정할 뿐 — 그 자세를 유지하며 이동이 가능한지, 자기/환경 충돌이 없는지, IK/gate-map 이 그 자세를 받아줄지는 보지 않는다 (kinematic 속력 상한). 나머지는 sim smoke 가 본다.
- `--evaluate-pose`: 탐색 없이 자세 하나의 자기 일치 `v_dir_lp/dls` · elevation · FK 를 찍고 종료한다 (운영자가 고른 자세 확인).

### catchability_map

투척 grid → 항력 비행 → 포구 후보 → **C++ judge** → 집계 · 제안 · 플롯. 판정은 재구현하지 않고 `rtc_controllers` 의 오프라인 실행파일 `catch_pose_ik_batch` (런타임 계획기와 같은 `CatchPoseIk::Solve`, 같은 YAML 키, L3 §4.2) 를 CSV 로 호출한다. import 용 순수 함수와 CLI 를 함께 갖는다.
- **headline 은 seed 하나의 수치다.** `--seed` 를 여러 개 줘도 로봇은 한 자세에서 기다리므로 `accepted_throws` · `throw_region.yaml` · `throw_summary.csv` · 사유 히스토그램 · $w/\theta$ 분포 · $\varepsilon$ 경계 · 플롯 · stderr 요약은 전부 seed 순위 1위 (`rank_wait_pose_seeds` best) 하나를 기술하고 그 seed 의 id 와 관절 벡터를 `results.headline_seed` · `throw_region.wait_pose_seed_id` / `wait_pose_q` 에 적는다. "어느 seed 든 하나라도 받으면 accepted" 인 합집합은 `accepted_throws_any_seed` 라는 **이름으로만** 남고 coverage 가 아니다. 비율의 분모는 어디서나 **전체 격자** (`accepted_fraction_denominator`) 이고, 후보가 judge 까지 간 throw 수는 `throws_with_candidates` 로 따로 적는다. `summarize_throws` 와 `propose_throw_region` 은 여러 seed 의 행을 `seed_id` 없이 받으면 거부한다 (합집합을 실수로 만들 수 없게).
- **seed 비교**는 포구 가능 throw 비율 내림차순, 동률이면 평균 $\log w_5$ 로 가른다. 서로 다른 throw 집합을 비교하려 하면 거부한다. runner-up 의 coverage 차이가 대기 자세 민감도 수치다.
- **출력**: `candidates.csv` (후보별 verdict · $q^\star$, 모든 seed), `throw_summary.csv` (격자 throw 당 1 행, 후보가 0 개인 throw 도 `candidates=0` · `accepted=0` 으로 나오며 `wait_pose_seed_id` 가 어느 대기 자세의 표인지 말한다), `reason_histogram.csv`, `throw_region.yaml` (`sim.throw_region` 제안 + provenance), `provenance.yaml`, `azimuth_coverage.png`, `manipulability.png`, 그리고 재개용 `model_config.yaml` / `model.urdf` / `seeds.csv` / `shards/` (shard 마다 `*_fingerprint.json` sidecar).
- **`--throws-file <list.json>`**: grid 대신 `catching_throw_list/1` 파일 (SIM WORLD) 의 투척을 파일 순서대로 평가한다. 각 `throw_id` 가 `throw_index` 로 나가 `catch_gate_map --map-dir` 이 이어받는다. 프레임 변환은 없다 (파일의 world = 이 도구의 `world` 이므로 리스트를 만든 쪽과 같은 `--robot-config` 층을 준다). $\omega$ 가 0 이 아닌 투척은 거부한다 (비행 모델에 스핀 항이 없다). grid 축 인자와 함께 주면 오류다. `throw_summary.csv` 의 6 축은 항목이 6 개를 다 들고 있으면 그 값 그대로, 하나도 없으면 arm base 기준으로 유도, 일부만 있으면 오류다. `provenance.yaml` 의 `throws_file` 에 path · sha256 · n_throws · meta 가 남는다.
- **judge 의 프레임은 arm base 가 아니라 Pinocchio MODEL WORLD (URDF 모델 root) 다.** 어떤 로봇은 모델 root 가 `base_link` 이고 CLIK `base_frame` 이 `base` 로 z 축 180° 차이다 (L3 §4.2 frame 규약). world → `base` 가 항등이라 world 좌표를 judge 에 그대로 넣으면 x · y 가 뒤집혀 "공이 등 뒤에서 온다" — 그런데 수치는 전부 그럴듯하다. 그래서 CLI 는 `--robot-config` 층의 `urdf.extra_frames.scene_world` 를 world 로 읽는다: 그 `parent` 가 arm base frame, 배치 ($p_{parent} = R(rpy)\,p_{world} + xyz$) 가 `base_T_world` 이고 `model_world_T_base` 는 parent 의 FK 로 **합성**한다 (catching 컨트롤러의 vision lane 과 같은 frame · 같은 합성). 없거나 `provisional` 이면 판정 전에 거부한다. 손으로 world 를 적던 `--world-yaw-deg` · `--world-translation-m` · `--arm-base-frame` 은 이유를 말하며 거부한다. 쓴 frame 은 `provenance.yaml` 의 `frames` 에 남고 `catch_gate_map` · `catch_speed_budget` 이 reach 중심과 world 를 거기서 읽는다 (`read_map_frames`).
- **출하 `urdf.sub_models.<arm>` 은 flange 에서 끝나 catch frame 이 그 sub-model 에 없다.** `write_model_config` 가 arm root → `urdf.extra_frames.<catch_frame>.parent` 까지의 sub-model `arm_catch` 를 추가로 선언한다. 그 뒤 (손 전체) 는 `buildReducedModel` 이 잠그는데 catch frame 의 FK · 팔 관절 Jacobian 은 정확하다 (손바닥이 손 폐쇄 루프의 상류). 스키마 차이 (`urdf_path`, `sub_models` 는 map 이 아니라 sequence) 도 여기서 번역한다. 로봇 config 가 `urdf.sub_models.<arm>_catch` 를 이미 선언하면 이름 그대로 쓰되, root/tip 이 arm root → catch frame 부모가 아니면 거부한다 (지도와 런타임 계획기가 다른 모델에서 판정하지 않게, G3-I).
- **샤딩 · 재개**: 후보를 chunk 로 나눠 최대 6 프로세스로 돌리고 자식 env 에 `OMP_NUM_THREADS=1` 을 준다. shard 출력은 **행 / ID 가 맞고 입력 fingerprint sidecar 가 일치할 때만** 재사용한다 (`shard_is_reusable`). 후보 id 는 실행마다 `0..N-1` 이라 id 만으로는 같은 `--out-dir` 에 `--params` · `--seed` · config · 격자 값을 바꿔 재실행해도 옛 verdict 가 재생된다. fingerprint 는 후보 CSV · model config · 그것이 가리키는 URDF/closure YAML · seeds · params (없으면 `none`) 의 sha256, sub-model · catch frame 이름, judge 실행파일의 정체 (경로 + 크기 + mtime, 내용 해시가 아니다 — judge 가 링크한 공유 라이브러리 변경은 못 잡으므로 그때는 `shards*/` 를 지운다) 로 만든다. sidecar 가 없거나 다르면 재판정 · 덮어쓰기이고 stderr 에 바뀐 것을 적는다. 비정상 종료 · 짧은 CSV 는 그 shard 의 stderr 를 달아 raise 한다 (조용히 짧은 shard 는 "그 투척들은 못 잡는다" 로 읽혀 반증되지 않는다).
- **`q*` 열이 비는 것은 세 번째 상태다** (pose 없음 ≠ q = 0). judge 는 `none` / `below_manip_min` / `rank_deficient` 에만 pose 를 쓰므로 나머지 사유는 `q*` 가 공란이고, 파서는 `None` 으로 구분하며 절반만 찬 행은 거부한다.
- **$w_5$ · $w_6$ 은 따로 보고한다** (같은 $q^\star$ 의 두 측정이지만 차원이 달라 pooling 하지 않는다). $\theta$ 분포는 `fraction_below` 와 `fraction_near_limit` 을 둘 다 낸다 ("$\alpha_{max}$ 의 몇 % 안" 이 양쪽으로 읽혀 결론이 뒤집히므로). 접근축 cone 이 binding 하는지는 `fraction_near_limit` 이 답한다.
- **$\theta$ 보고의 `alpha_max` 는 judge 가 실제로 적용한 값이다** (`resolve_alpha_max`). `--params` 가 `planner.search.grid.ik.alpha_max` 를 주면 그 값이다. 파일 형태는 judge loader 와 같은 세 가지만 받는다 (root 의 `catching:` map / root 에 `planner:` 가 있는 catching tree / 출하 controller config 형태 `<controller_name>: {catching: ...}`) — 그 밖은 기본값으로 떨어지지 않고 에러다. `include:` 로 나뉜 컨트롤러 config 는 judge 가 합성하지 않으므로 `planner.search.grid.ik` · `planner.search.grid.catchability` 가 든 조각 `controllers/catching/search_grid.yaml` 을 넘긴다. `--alpha-max-rad` 는 기본값이 없는 선택 인자로, params 가 값을 주는데 다른 값을 넘기면 에러 (진실의 출처가 둘), 같으면 허용, params 가 미지정일 때만 단독으로 쓰인다. 둘 다 없으면 judge 의 in-code 기본값 0.26 의 미러를 쓰고 provenance 에 미러임을 적는다. judge 가 `--print-options` 를 제공하면 그 출력과 대조해 다르면 sweep 전에 에러이고, 제공하지 않으면 provenance 에 "not cross-checked" 로 남는다.
- **$\varepsilon$ 경계 개수**: 받아들여진 후보의 $p_c$ 를 축별 $\pm\varepsilon$ 로 옮긴 6 사본을 **다시 judge 에 넣어** 하나라도 거부되면 그 후보는 경계 위다 ($w_5$ 여유 같은 대용값 추정이 아니다).
- **힘 법칙은 sim 과 같다**: 중력 + 이차 항력 $-\tfrac12\rho C_d A|v|v$ (`ComputeProjectileBallAeroForce`). **각속도 0 가정**이라 Magnus 항은 구현하지 않는다 (spin 을 실어 발사한 궤적은 이 모델과 다르다).
- **공기밀도 · 항력계수 · 반지름 · 질량은 기본값이 없다.** $C_d$ · $\rho$ 는 C++ `constexpr` preset 에만 있고 YAML 로 노출되지 않으므로 python 에 박아 두면 preset 이 바뀌어도 아무것도 실패하지 않는다. 호출자가 값과 **출처 라벨 (`file:line`)** 을 함께 넘기고 provenance 가 그 라벨을 기록한다. 반지름 · 질량은 `projectile_ball.radius_m` / `.mass_kg` 에서 읽는다. 스칼라 $k = \rho C_d A/(2m)$ [1/m] 는 참고용 파생값으로만 기록한다.
- **프레임 변환은 인자로만 받는다.** URDF 가 `base` / `base_link` 를 같은 원점에 z 180° 로 두는 경우 잘못 고르면 downrange 부호만 뒤집힌다. 로봇별 값을 모듈에 박지 않고, 같은 $q$ 에서 MuJoCo FK ↔ Pinocchio FK 로 확정한 변환을 호출자가 넘긴다. 각 throw 는 world 기준 release position · velocity 를 들고 있어 `rtc_msgs/srv/LaunchBall` 요청 필드로 1:1 대응한다 (`throw_to_launch_request`).
- **손 근처 투척 (S8-F)** `aim_at_hand(p_c, approach_axis, speed_m_s, flight_time_s, offset_m, offset_angle_deg, incidence_offset_deg, params, floor_z_m)`: 도착 상태 (목표점 = $p_c$ + 접근축에 수직한 평면의 오프셋, 도착 속도 = 접근축의 연직면에서 $\alpha$ 만큼 돌린 방향) 에서 같은 힘 법칙을 **RK4 로 역적분**해 릴리스 (위치 · 속도) 와 도출량 (Δz · d · v0 · 앙각 · 입사각 · 정점) 을 돌려준다 (shooting 없이 결정론). 진공 해와의 차는 5 m/s · 0.8 s 에서 약 0.1 m 라 항력을 빼면 손을 그만큼 비껴간다. 공 표면이 `floor_z_m` 아래로 가는 비행은 `ValueError` 로 거부한다. `closest_approach` 는 표본 궤적을 Hermite 로 이어 목표점 최근접 (거리 · 시각 · 속력) 을 내고, `aim_check_from_truth` 는 truth 의 첫 표본에서 모델을 적분해 목표점 통과 오차를 낸다 (truth 는 손에서 끊기므로 표본 자체로는 통과를 읽을 수 없다. `free_flight_prefix` 가 속도 도약 > max(0.3 m/s, 3 g Δt) 로 첫 접촉을 잘라 그 앞 표본과 모델의 RMS 를 함께 낸다).

### catch_speed_budget

`catchability_map` 이 "팔이 그 자세에 갈 수 있는가" 를 답한다면 이 도구는 그 수락 후보에 대해 "거기서 공과 함께 움직일 수 있는가" 를 답한다. 계획기 $\gamma$ 창 (L3 §4.5) 은 $\|v\| + \text{margin} \le v_{arm} + v_{rel}$ 일 때 열린다. $v_{arm}$ 은 포구 자세 $q^\star$ 에서 공 진행 방향 $\hat v$ 로 낼 수 있는 팔 속력, $v_{rel}$ 은 손이 흡수하는 상대속도 (`d_eff / T_close,tot` 또는 실측값) 다. 후보별로:
1. `v_dir_max_lp`: 접근축을 유지한 채 관절 속도 box 안에서 $\hat v$ 로 낼 수 있는 최대 속력 (선형계획, 물리 상한).
2. `v_dir_max_dls`: L3 §4.5 의 최소노름 추정 (런타임 `DirectionalSpeedMax` 가 받는 값의 거울). LP 이하이며 그 차이가 최소노름 해가 버리는 여유 자유도다.
3. **토크 한계 방향 가속**: $\max a$ s.t. $J_5\ddot q + \dot J_5\dot q = [a\hat v; 0\;0]$, $|M\ddot q + h| \le \eta_\tau \tau_{max}$ 를 속력 ramp 를 따라 풀고 stroke · 시간을 적분한 $v_{arm}$.

전부 **낙관적 상한**이다 (bang-bang, 자세 고정, 도달 구). 창이 비면 결론은 확정적이고 열리면 provisional 이다.
- 출력: `speed_budget.csv` (후보별), `drop_table.csv` (행 = 낙차 $z_{catch} - z_{release}$ 구간, 열 = $v_{rel}$, 셀 = 창이 열리는 후보 비율), `cell_table.csv` (행 = (릴리스 높이, 거리) 셀, 값 = **투척 수**, 분모는 `throw_summary.csv` 의 전체 격자), `speed_budget_summary.yaml` (provenance).
- **기본값이 없는 인자는 전부 결정이다**: `--velocity-source` (`config` = 실행이 강제하는 `joint_limits.max_velocity`, `model` = URDF `<limit velocity>` 정격), `--rotor-inertia` (URDF 에는 회전자 반사관성이 없다 — 빼면 모든 가속이 과대평가되므로 0 을 주려면 명시해야 한다), 선행시간 다섯 항. 최소 비행시간 $T_{det} + L + T_{close,tot} + T_{arm} + T_{margin}$ (L1 §4.1 D-15) 에는 손 폐쇄 시간이 들어간다. ramp 에 쓸 수 있는 시간은 $t_c - (T_{det} + L)$ 다.
- **프레임**: judge 의 `p_model` · `v_model` 은 모델 world (URDF root) 이고 `LOCAL_WORLD_ALIGNED` Jacobian 이 쓰는 프레임과 같아 그대로 쓴다. 바닥은 world 에서 수평이다: 후보의 여유 높이는 `p_world_z` 열, stroke 의 하강은 world +z 방향 (지도 `provenance.yaml` 의 `frames`) 으로 잰다. reach 구의 중심 (arm base 원점) 도 그 `frames` 에서 읽는다 (옛 `--arm-base-frame` 은 거부). `p_world_z` 가 그 frame 으로 옮긴 `p_model` 과 어긋나면 종료한다.
- **자체 검증 (fail-closed)**: 모든 수락 $q^\star$ 에서 catch frame FK 가 `p_model` 과 `--fk-tolerance-m` (기본 2.5 mm = judge `eps_pos` + 여유) 안에 들어와야 한다. 벗어나면 관절 순서 · frame · 모델 중 하나가 judge 와 다르므로 보고하지 않고 종료한다. 최소노름 속력이 LP 를 넘어도 종료한다.

### catch_gate_map

`catchability_map` 의 수락 후보 (포구 자세가 있는 후보) 에 계획기의 나머지 게이트를 건다: 도달시간 (L3 §4.3), $\gamma$ 창 (§4.5), 정지점 (§4.9), 그 앞의 commit 선행 (§4.11, $t_c - t_{plan} \ge T_{close,tot} + T_{arm} + T_{margin}$, 런타임 함수가 없어 python 이 건다). **판정은 python 이 하지 않는다**: `rtc_controllers` 의 `catch_gate_batch` 가 `time_feasibility.hpp` 의 런타임 함수를 그대로 부르고 (G3-I), python 은 입력과 출력만 맡는다.
- **python 이 만드는 입력**: $\dot q^u$ (L3 §4.5 의 DLS 단위 속도) 와 그것이 내는 속도 $J_p\dot q^u$. `reference.v_max` 는 `--v-max-m-s derived` 면 수락 후보의 LP `v_dir_max` 최대 / $\eta_v$ 다 (S4.4 결정: TCP 항은 관절 정격 안에서 구속하지 않는다). 감쇠 $\lambda$ 의 기본은 `--controller-config` 의 `catching.planner.search.grid.gamma.unit_speed_damping` (런타임 탐색이 읽는 키) 이고 키가 없으면 C++ 기본과 같은 `catch_speed_budget.DEFAULT_DLS_DAMPING` 이다. 쓴 값은 summary 에 남는다.
- **python 이 거는 경계**: $p_{stop}$ 이 도달 구 · 바닥 안인가 (런타임 탐색에는 정지점 판정이 없다, L3 §4.9 — 이 경계는 지도의 것이다). reach 판정은 지도의 frame 으로 한다 (정지점의 높이는 world 로 옮겨 잰다. 기울어진 world 에서 모델 z 차이로 옮기는 근사는 틀린다).
- **도달시간은 두 층**을 항상 같이 낸다. `box` = 컨트롤러 YAML 의 가속 box (`catching.robot.arm.qdd_max`, `--controller-config`, 기본은 `--robot-config` 옆 `controllers/<--controller>.yaml`, `include:` 조각 합성) 로 C++ 가 판정한다. 런타임 트리는 controller YAML + ROS 파라미터 override 이므로 지도의 box · $\lambda$ 는 **런타임과 같은 파일을 `--overlay <파일>` (반복 가능, 준 순서대로 leaf 단위로 얹음) 으로 줄 때에만** 같다. 안 주면 출하 값의 지도다. 적용한 파일은 `gate_map_summary.yaml` 의 `overlays` 에 남는다 (합성 helper 는 `rtc_tools.utils.controller_config.overlay_catching` / `deep_merge`). `torque` = **그 이동**이 토크 한계 안에 드는가: 전 관절이 하나의 bang-bang / 사다리꼴 경로 프로파일로 대기 자세 → $q^\star$ 로 가고 경로 전체에서 $|M\ddot q + h| \le \eta_\tau \tau_{max}$ (회전자 관성 포함) 인 최대 경로 가속을 이분 탐색한다. 충분조건이고 런타임 대응물이 아직 없어 **provisional** 이다 (D-16 개정).
- **대기 자세는 하나다.** 지도가 여러 seed 로 판정됐으면 `--seed-id` 가 필수다 (합집합은 과대평가). `proposed_wait_pose` 는 $\gamma$ · 정지 게이트를 통과한 $q^\star$ 의 관절별 midrange 이고 새 seed 로 `catchability_map` 부터 다시 돌리는 고정점 반복의 입력이다.
- rollout (L3 §4.8) 은 판정하지 않는다. 열린 셀은 `PASS(provisional)` 이고 빈 지도는 확정적이다.
- **출력**: `gate_candidates.csv` (judge 입력) · `gate_judged.csv` (judge 출력 그대로) · `gate_map.csv` (후보별 두 층의 사유 · `t_min` · $\gamma$ 창 · $q^\star$) · `gate_cell_table.csv` (릴리스 높이 × 거리, 분모는 전체 격자) · `gate_map_summary.yaml` (인자 provenance, 층별 열린 투척 수 · 사유 분포, 각 게이트가 단독으로 거르는 후보 수, 층별 열린 후보의 $t_c$ · 포구 속력과 투척별 포구 창 분포 `open_candidates` — 층이 아무것도 열지 않으면 `null`, 대기 자세 제안). FK($q^\star$) 가 `p_model` 과 어긋나면 보고하지 않고 종료한다.

### catch_search_map

투척마다 계획기가 볼 wake 열을 만들어 `rtc_controllers` 의 `catch_search_batch` (런타임 `CatchSearch::Plan`, grid · nlp) 에 넘기고 그 판정을 투척별로 줄인다. **판정은 python 이 하지 않는다.**
- **투척**: gate 지도와 같은 여섯 발사 축의 격자 (`throw_id` = `catchability_map` 의 `throw_index`, `--grid-origin arm_base` 일 때) · 같은 상자의 Latin hypercube 표본 (`--sample N --sample-seed S`) · 또는 `--throws-file` 목록. 돌린 투척은 `throw_list.json` (`catching_throw_list/1`, sim world — `catching_sim_trials --throws-file` 이 그대로 던진다), 표본만은 `throw_list_sample.json` 이다. 형식의 검증 · 읽기 · 쓰기는 `analysis.catching_throw_list` 하나이고 sim 드라이버도 같은 모듈로 읽는다.
- **wake**: 예측은 비행 모델 자체 (`integrate_flight` 의 출하 항력 RK4) 다. 투척마다 비행을 **한 번** 적분한다 (`throw_flight`): 표본은 wake 들의 예측 표본 시각 위의 `flight_states` 와 비트 단위로 같고, 아래 축 값은 같은 비행의 적분기 상태 전부 (간격 ≤ `--step-s`) 에서 읽는다. wake 는 발사 뒤 `--detection-delay-s` 부터 `--vision-period-s` 마다, 공이 바닥 (`--min-catch-height-m`, sim world) 위 · `--horizon-s` 안에 있는 동안 생긴다. 각 wake 의 snapshot 은 wake 뒤 $k\,dt$ ($k = 1 \ldots$ `--prediction-horizon-s` / dt) 의 상태이며 dt 의 기본은 트리의 `prediction.dt_expected` 다. 시각은 모든 투척이 같은 발사 시각에 놓인 정수 ns, 좌표는 model world (합성 layer 의 모델 frame `scene_world` 와 URDF 의 그 parent 배치 합성) 이다.
- **binding**: 컨트롤러가 configure 에서 묶어 탐색에 넘기는 값을 합성 트리 (컨트롤러 YAML + `_base.yaml` · `sim.yaml` + `--overlay`) 와 로봇 config (장치 한계 = YAML ∩ URDF, CM 의 병합 규칙) 에서 만든다. 값마다 출처 (키 · 식) 와 따라 한 컨트롤러 함수, 있으면 그 값을 실행 중에 담는 read-only 미러 파라미터를 `binding_<search>_sources.yaml` 에 적는다. 컨트롤러가 **내장 상수**로 돌 키 (없거나 `TBD` 인 `planner.search.grid.gamma.eta_v` 등) 는 그 키 이름으로 거부한다 (사본을 두지 않는다). 키가 없을 때 컨트롤러도 TBD 로 두는 값은 `.nan` 이다. 팔 관절의 URDF 한계를 CM 이 다른 관절의 항목에서 읽게 되는 경우는 거부한다. 손은 nlp 만 읽고 (CLIK 위치 상자가 완결인지, `BuildClikBoxes`) CM 이 읽는 그대로 읽는다. grid 는 손을 읽지 않는다.
- **줄임**: 투척별 수용 (어느 wake 든 plan) · 첫 수용 wake · 그 $t_c$ · lead, 거부한 투척의 대표 사유 (sim 의 `plan_reject` 와 **같은 함수**, 동률은 나중 것) 와 줄이지 않은 wake × 사유 수. 축 값 `flight_time_s` · `terminal_speed_m_s` · `closest_distance_m` 은 비행이 `planner.wait_pose` 의 포구점에 가장 가까워지는 순간의 값이다 (탐색과 무관).
- **요약** (기술 통계만): 축별 수용률 · 사유 분포 (투척 / wake) · grid 와 nlp 가 갈리는 투척 · `--gate-map` 의 `catch_gate_map` 출력과 같은 축 값의 투척끼리 층별 대조 (gate 열림 · 닫힘 · 후보 없음 × 수용 · 거부, 어긋난 칸의 사유) · `--sim-trials` 의 `catching_trials.csv` 와 `throw_id` 로 이은 sim 표 (수용 · 게시 = `published` / 수용 · 미게시 = `withheld` / 거부 = `no_plan` · `no_search`, × `truth_success`, 무효 시행 제외) 와 오프라인 일치율 (수용 ∧ 게시 + 미수용 ∧ 미게시). 수용 · 미게시 행은 plan 을 붙든 층 (`segment` · `cycle` · `search`) 으로 한 번 더 나뉜다 (`not_published_by_layer`).
- **구간 판정** (`--judge-segments`, 기본 꺼짐): 한 shard 의 탐색이 끝난 뒤 **탐색이 수용한 투척만** 같은 wake 로 계획기 주기 전체 (`PlannerCycle::Run`: 탐색 → 첫 구간 풀이 → 쌍 게시) 를 돌린다. 한 wake 의 쌍이 게시됐다 ⇔ `outcome == published` ∧ `search_valid == 1` 이고 투척의 행은 거기서 멈춘다. binding 은 탐색 binding 에 최상위 `segment:` 맵을 더한 `binding_<search>_segment.yaml` (+ `_segment_sources.yaml`) 이고 트리의 `planner.segment.mode` (`mpc` / `mpc_docking`) 가 모양을 고른다 (`closed_form` 은 구간 계획기가 없어 실행 전에 거부). 두 번째 실행이 `segment_<search>.csv` 를 쓰고 `verdicts_<search>.csv` 에 `segment_accepted` · `segment_first_wake` · `segment_after_release_s` · `segment_t_c_s` · `segment_lead_s` · `segment_reject_reason` · `segment_wake_reasons` · `segment_wakes_run` · `segment_wall_us` 가 붙는다. 탐색이 거부했거나 걸러진 투척의 이 열은 **빈 칸**이다 (거부 = `False` 와 구별되는 "판정 안 함"). 요약은 탐색 항목마다 `segment` 블록 (`mode` · `judged` · `accepted` · `refused` · 사유 분포 · 시간 · 설정 거부 문장) 을 갖고 `provenance.segments` 에 binding sha256 을 적는다. 중간 파일 `segment_wakes_<search>.csv` 는 `--keep-shards` 없이는 남기지 않고, 같은 `--out-dir` 에 다시 돌리면 앞선 구간 판정 파일을 먼저 지운다. 오프라인에 없는 것: 쌍 게시 뒤의 replan · 교체, 추정 잡음 (공분산 0), 실행 시계가 만드는 것 (예산을 넘긴 풀이, 풀이 중 더 새 예측이 와서 버려진 쌍, 오래된 RT 보고), 벽시계 거부, plan 을 따르는 중의 탐색, 컨트롤러의 park 조건 — sim 에서 본다.
- **사전 판정이 붙은 투척**: 목록 항목의 `screen` 이 비어 있지 않으면 (`catch_throw_design` 이 붙인다) 탐색에 넘기지 않고 그 이름으로 거부한다. `--judge-screened` 는 그 투척에도 탐색을 돌린다 (조건을 탐색 자체로 확인하는 실행이며, 받은 것이 있으면 요약의 `searches.<search>.screened.accepted` 에 id 가 나온다). 목록의 `meta.unlaunchable` (발사 상태가 없는 설계점) 은 지도의 행으로만 들어간다. 이름은 그것을 낸 구 · lead 하한 · 검출 지연 (`meta.design`) 에 대해서만 필요조건이다: 이 실행의 구가 더 크거나 자리가 다르거나, lead 하한이 더 작거나 (모르거나), 첫 wake 가 더 이르면 (`screen_basis`) `--judge-screened` 없이는 거부한다.
- **어느 탐색을 돌릴지**는 `--search` 가 정한다 (트리의 `planner.search.mode` 가 아니다). 그 탐색의 맵 (`planner.search.<search>`) 이 합성 트리에 없으면 binding 이 거부한다. `planner.segment.mode` 는 lead · nlp 한계의 속도 여유 · `follows_segments` 를 정한다.
- **shard**: `--jobs N` 은 투척을 shard 로 잘라 (`--shard-throws`, 기본은 job 몫의 1/4) wake 생성과 batch 를 N 프로세스에서 돌린다. 판정은 투척 하나로 정해지므로 자르는 방식과 무관하다. shard 가 둘 이상이면 `wakes.csv` 는 남기지 않는다 (`--keep-shards` 로 `shards/` 를 둔다).
- **출처**: 요약의 `provenance` — 합성 트리 (`catching_tree.yaml`) 의 sha256, 합성에 쓴 파일과 sha256, checkout 의 commit · dirty 여부, batch 바이너리의 경로 · sha256, 도달 구 (`catch_search_batch --print-reach-bound`), `--estimator-profile` 의 `prediction.horizon_s` 와 `--prediction-horizon-s` 가 같은지. 공의 반지름 · 질량 출처 라벨은 설정 폴더 안의 파일이면 `<설정 폴더 이름>/<상대 경로>:<key>` 다. `verdicts_*.csv` 의 `search_wall_us` 는 그 투척의 `Plan` 호출 벽시계 합이다 (실행마다 다르다).
- **출력**: `throw_list.json` · `wakes.csv` · `catching_tree.yaml` · `model_config.yaml` · `binding_<search>.yaml` · `binding_<search>_sources.yaml` · `search_<search>.csv` (batch 출력 그대로) · `verdicts_<search>.csv` (투척별) · (`--judge-segments`) `binding_<search>_segment{,_sources}.yaml` · `segment_<search>.csv` · `gate_join_<search>.csv` · `sim_join_<search>.csv` · `search_map_summary.json`. 탐색이 설정을 거부하면 (batch 종료 코드 3) 그 문장을 요약의 `refused_configuration` 에 적고 지도는 없다. 구간 계획기가 거부하면 `segment.refused_configuration` 에 적고 구간 열은 비며 탐색 지도는 그대로다.

### catch_throw_design

탐색을 돌리지 않는다. 발사점 (base 축 기준 거리 · 방위, world 높이) · 통과점 (대기 자세 포구점의 world x · y 오프셋, 높이는 포구점 + `--pass-plane-offset-m`) · 발사각의 격자에서 그 통과점을 **지나는** 발사 속력을 항력 모델로 푼다 (`solve_launch_speed`: 무항력 닫힌 해에서 시작해 regula falsi). 투척의 `throw_id` 는 여섯 축 (`distance_m` · `azimuth_deg` · `release_height_m` · `pass_dx_m` · `pass_dy_m` · `elevation_deg`) 의 곱에서의 순번이다.
- **적분**: `integrate_flights` 는 `catchability_map.integrate_flight` 를 투척 N 개에 한꺼번에 돌린 것 (같은 힘 법칙 · RK4 · 스텝 수) 이고 `closest_approaches` 도 `closest_approach` 와 같은 알고리즘이다.
- **적는 값**: 발사 상태, 속력과 `aim_deviation_deg` (그래서 kinematic 지도의 여섯 축이 다 있고 `--gate-map` join 이 성립한다), 정점과 `apex_margin_m` (정점 − 통과면; `--apex-margin-flag-m` 아래는 `apex_flag`), 포구점 최근접의 `flight_time_s` · `terminal_speed_m_s` · `closest_distance_m` · 하강각 · 손 접근축과의 각, 도달 구 안의 마지막 시각 `reach_last_s` 와 `lead_available_s` (= −검출 지연), 통과점과 대기 자세 관절 원점 폴리라인의 거리 (`body_flag`, 표시만).
- **사전 판정** (`screen`): `screen:shoot_ascending` (하강 교차 없음) · `screen:shoot_fail` (미수렴 또는 `--speed-max-m-s` 초과) · `screen:reach` (비행이 구 밖) · `screen:time` (lead 상한 < 두 탐색의 lead 하한 중 작은 값). 구는 batch 의 `--print-reach-bound` (반경 + 두 탐색의 `ik.eps_pos` 중 큰 값) + `robot.hand.docking.s_ent`, lead 하한은 합성 트리의 키에서 구하며 값과 출처가 `design_meta.json` 에 있다. nlp 의 하한 키가 없거나 `TBD` 면 시간 판정을 하지 않는다. 앞의 둘은 발사 상태가 없어 투척 목록에 들어가지 않고 목록의 `meta.unlaunchable` 로 간다.
- **발사각 축**은 값 목록이 아니라 범위다: `--max-elevation-deg` · `--min-elevation-deg` · `--elevation-step-deg` (셋 다 필수) 가 `max − k·step` (≥ min) 을 오름차순으로 만든다. 최대각은 언제나 값이고 최소각은 격자에 놓일 때만 값이다.
- **제한** (`--min-pass-time-s`, 선택): 발사된 투척의 항력 풀이 `pass_time_s` 가 그보다 짧으면 (같으면 아님) `design.csv` 의 `limit` 열에 `limit:pass_time` 이 붙는다. `screen` 과 독립이다: `screen` 은 어느 탐색도 받을 수 없다는 뜻이라 지도가 검증하지만, 제한된 투척은 수용될 수 있다. `design_meta.json` 의 `limits` 에 기준값 · 규칙 · 수를 적는다.
- **`select`**: `--subset <axis>=<values>` 의 부분 격자, `--ids-file`, 또는 `--refine-from <verdicts.csv …>` (부분 격자에서 한 축으로 한 칸 떨어진 두 점의 판정이 다르면 그 사이의 격자점을 더한다, 재귀 없음). **제한된 투척은 세 경로 모두에서 목록에 쓰지 않는다.** 목록 `meta.limit` 이 기준값과 뺀 수를 적어 지도의 수용률 분모를 복원하게 한다. `--max-throws` 는 뺀 뒤의 수로 세어 넘으면 쓰지 않고 끝난다. `limit` 열이 없는 옛 `design.csv` 도 읽는다.
- **`--segment-mode`** (`design` 과 `catch_search_map`): 합성 트리의 `planner.segment.mode` 한 값만 `--overlay` 뒤에 덮어쓴다 (없으면 출하값). 바꾼 값은 `catching_tree.yaml` 과 요약 · `design_meta.json` provenance 의 `overrides` 에 남는다.
- **`plan-set`**: `--throws-file <지도가 판정한 목록>` `--verdicts <verdicts_<search>.csv …>` `--out` 으로 수용된 투척을 `throw_id` 오름차순 `catching_throw_list/1` 로 쓴다. 판정이 목록을 덮지 못하거나 수용된 id 가 목록에 없으면 개수를 대며 거부한다. `--tier search` (기본) 는 `accepted` 열 (탐색 집단), `--tier segment` 는 `segment_accepted` 가 참인 투척 (구간 집단) 이다. 구간 집단은 `--judge-segments` 로 만든 판정표만 받는다 (그 열이 없거나 탐색 수용 투척 가운데 그 칸이 빈 것이 있으면 거부 — 구간 계획기가 설정을 거부한 판정표다. 탐색이 하나도 수용하지 않은 파일은 받는다). meta 에는 원본 목록과 판정 파일별 sha256, `tier` · `set_name` (`throw_search_set` / `throw_segment_set`), 판정 수 · 수용 수, 원본의 `design` · `axes` · `limit` 이 든다.
- **`sample`**: `--plan-set` `--out-dir` `--strata <축…>` `--seed` `--chunk` `[--max-throws]`. 층 (축 값 조합) 마다 같은 비율, 정수는 최대 잔여 방식 (합 = min(N, 크기), 동률은 층 키 순서). 층 안의 선택은 `sha256("<seed>:pick:<id>")`, 전체 순서는 `sha256("<seed>:order:<id>")` 로 정해 난수 라이브러리를 쓰지 않으므로 버전 · PC 가 달라도 같다. `sample.json` (섞인 순서 전체) 과 그 연속 조각 `chunk_000.json` … (각 `catching_throw_list/1`, `catching_sim_trials --throws-file` 이 읽는다). meta 는 `plan_set_sha256` (여러 PC 의 결과를 `throw_id` 와 함께 합치는 열쇠) · 층 축 · seed · 층별 (전체, 뽑은 수) · `max_throws` · 묶음 크기이고, 묶음 파일은 `chunk_index` · `chunk_count` · `sample_sha256` 도 든다. 출력은 입력 파일의 바이트와 인자만의 함수다 (절대 경로 · 시각 없음).
- **출력**: `design.csv` (설계점마다 한 행) · `design_meta.json` (격자, 발사각 범위, 제한 수, 구, lead 하한, 사전 판정 수, 출처) · `catching_tree.yaml` · `model_config.yaml`.

### catch_population

설정 파일 하나 (`<config>/<robot>/catch_population.yaml`; 형식과 키는 `utils/catch_population.py` 의 docstring, 없는 키 · 모르는 키 · 범위 밖의 값은 키 이름으로 거부) 가 모집단과 그것을 거르는 방법을 정한다. **로봇은 파일이 놓인 폴더다**: 판정에 쓰는 컨트롤러 설정이 그 폴더이고, 조합 (`arms`) 이 출하값에서 바꾸는 것은 `planner.search.mode` 와 `planner.segment.mode` 둘뿐이다.

```
설계 ─제한─▶ 모집단 ─탐색─▶ search 집단 ─구간─▶ segment 집단 ─뽑기─▶ 던질 묶음 ─(2 단계: sim)─▶ 쌍 게시 ─▶ 포구
```

- **`catch_population`** 은 판정도 설계도 직접 하지 않는다. 있는 도구의 `main` 을 설정 파일의 값으로 차례로 부른다: `catch_throw_design design` → `select` (모집단 = 발사 불가 · 제한을 뺀 목록) → 조합마다 `catch_search_map --search <search> --segment-mode <segment> --judge-segments` **한 번** → `plan-set --tier search` · `--tier segment` → 조합이 던지는 집단 (`throw_set`) 의 `sample`.
- **이어 돌리기**: 산출물이 이미 있는 단계는 건너뛴다 (끊긴 실행은 같은 명령으로 잇는다). 결과 폴더는 설정 하나의 것이다: 폴더의 `config.yaml` (파일의 사본) 과 바이트가 다른 파일을 주면 거부하고 새 `--out` 을 쓰라고 한다. 비어 있지 않은데 `config.yaml` 이 없는 폴더도 거부한다.
- **빈 집단은 결과다**: 판정기가 한 발도 수용하지 않은 층은 집단 파일을 쓰지 않고 (0 발) 그 조합에 던질 것이 없으면 묶음도 없다. 탐색이나 구간 계획기가 설정을 거부한 조합은 그 문장과 함께 "집단 없음" 이다. 어느 쪽이든 manifest 와 보고에 적고 나머지 조합을 계속한다.
- **`inputs.json`**: 판정에 쓴 설정 폴더의 YAML 전부의 sha256. 첫 실행이 적고 그 뒤 실행은 파일이 바뀌었으면 **바뀐 파일의 이름을 대며 거부한다** (컨트롤러 YAML 을 고친 뒤 같은 `--out` 으로 다시 돌리면 "이미 있는" 지도와 집단이 새 설정의 것으로 넘어가기 때문이다). 판정기 (`catch_search_batch`) 바이너리의 sha256 도 `judge_sha256` 으로 적는다: 판정기는 **거부하지 않고 경고한다** — 적힌 것과 다른 바이너리로 이어 돌리면 stderr 에 `WARNING` 을 내고 `inputs.json` 은 그대로 둔다 (지금 도는 단계는 새 판정기의 판정이고 건너뛴 단계는 옛 판정을 지니므로, 판정기의 동작이 바뀌었으면 새 `--out`). 그 key 가 없는 `inputs.json` 에는 경고하지 않고 그 실행의 sha256 을 적어 둔다.
- **설정 파일은 쓴 대로 읽거나 거부한다**: 따옴표 없는 `-40:40:20` 은 YAML 이 60 진수 정수로 읽으므로 거부하고 (범위는 따옴표를 친 문자열 `'lo:hi:step'`), 같은 키를 두 번 쓴 파일도 거부한다.
- **던질 목록은 지금 있는 집단의 것이어야 한다**: `sample.json` 이 적은 집단의 sha256 이 집단 파일과 다르면 다시 뽑는다. 투척 목록 파일은 다 쓴 뒤에 제 이름으로 나타난다.
- **`manifest.json`**: 설정 파일의 sha256 과 읽은 경로, 모집단 파일의 sha256, 조합마다 집단의 크기와 sha256 · 던질 목록 · 지도 요약이 적은 provenance. git revision 은 읽을 수 있을 때만 적는다.
- **`catch_population_report`** 는 폴더의 파일만 읽는다 (판정하지 않고 로봇 설정 폴더도 필요 없다). `report/population_report.txt` (같은 내용을 터미널에) 는 설정 (격자 · 발사각 범위 · 제한), 집단의 크기 (설계점 → 발사 불가 · 제한으로 빠진 수 → 모집단 → 조합별 search · segment → 던질 수), 거부 사유, 조합끼리의 겹침, 여섯 축의 값별 · 속력 · 통과 시간 · 정점 높이의 구간별 수와 모집단 대비 비율을 담는다. 판정하지 않은 집단은 `not judged` 다. 조합들의 지도를 서로 다른 판정기 바이너리가 판정했으면 머리에 `judge binaries: N different` 줄이 붙는다.
- **3D plot** (PNG, `--show` 면 창도): 집단마다 `set_<이름>.png` (발사점 → 통과점의 비행을 발사각 색으로, 대기 자세의 팔과 포구점), 조합마다 `sets_<조합>.png`. 그리는 비행은 집단당 `--max-flights` 개까지이고 `throw_id` 의 해시로 골라 매번 같은 투척이며, 그린 수를 제목에 적는다. 팔은 설계가 판정 모델의 FK 로 구해 `design_meta.json` 에 적은 관절 원점과 포구점이다.
- **sim 결과가 있으면** (`<조합>/sim_throws.csv` — 2 단계가 쓴다: `arm,seed,chunk` 뒤에 unit 의 `catching_trials.csv` 열 전부): 조합 · 추정기 seed 마다 던짐 → 쌍 게시 → 포구 (`truth_success`) 의 수와 축 값별 · 구간별 표, `set_<조합>_published_seed_<seed>.png` · `set_<조합>_caught_seed_<seed>.png` · `sets_<조합>_seed_<seed>.png` 를 더한다. 행은 `catch_search_map.sim_table` 로 읽으며 `invalid_reason` 이 있는 시행은 던진 투척이 아니다.
- **뽑아 던진 조합**: 표의 수는 **던진 투척 안의 수**이고 (비율 옆 구간은 그 안의 Wilson 95 %), 집단 전체는 **추정**이다: `sample.json` 의 층마다 (집단의 수 ÷ 던진 수) 로 되돌려 더한다 (`stratified_estimate`). 던진 투척이 없는 층은 추정 밖이고 따로 센다. 집단을 전부 던졌으면 추정을 내지 않고 그 수가 집단의 수라고 적는다.
