# 단계 W — `rtc-framework` workspace 종합 분석 (L0 착수 전 필수)

- 문서 버전: v0.4 (2026-09-19)
- 선행: 없음. **L0 포함 모든 layer 구현의 선행 단계다.**
- 산출물: 본 문서의 기록 칸이 모두 채워진 상태 + 그 결과를 반영해 수정된 L0–L8 문서

---

## 1. 왜 이 단계가 먼저인가

포구 알고리즘은 새 workspace에 새로 짓는 것이 아니라 **이미 동작하는 `rtc-framework` 위에 얹는 것**이다. 다음 세 가지가 이미 존재한다(사용자 확정).

1. **vision 노드**가 예측 궤적을 `sensor_msgs/PointCloud2`로 발행하고 있다. 제어 알고리즘은 이 메시지를 받는 것으로 상정한다.
2. **arm-hand system의 kinematics·dynamics 알고리즘**이 이미 구현돼 있다. 포구 구현은 이것을 **참고·재사용**해야 하며, 같은 기능을 새로 만들지 않는다.
3. **joint command backend**가 실기와 시뮬레이션 양쪽에 맞게 이미 구현돼 있다. 명령은 **전부 position**이다. 제어기가 할 일은 연산 결과를 **workspace 구조에 맞는 자리에 데이터로 실어 주는 것**뿐이다.

따라서 L0–L8 문서의 "코드 확인 게이트"(각 문서 §2)는 전부 이 단계에서 한 번에 처리한다. **게이트가 비어 있는 상태로 구현을 시작하지 않는다.** 문서의 가정과 실제 코드가 다르면 문서를 먼저 고친다(각 문서 §2의 규칙).

본 문서는 **조사 계획**이다. 항목별 결론은 조사 후 "기록" 칸에 채워 넣고, 해당 layer 문서의 TBD를 닫는다. 추측으로 채우지 않는다.

## 2. 조사 원칙

- 1차 출처는 **workspace의 소스 코드**다. 기억이나 유추로 API를 적지 않는다.
- 런타임 사실(토픽 필드 레이아웃, 주기, 지연)은 **실제 실행 결과**로 확인한다(`ros2 topic echo --once`, `ros2 interface show`, rosbag).
- 모든 기록에 확인 방법과 확인 일자를 남긴다.
- 기존 코드와 본 설계가 충돌하면, 기존 코드를 따르고 문서를 고치는 쪽을 기본으로 한다. 기존 코드를 바꿔야 한다고 판단되면 그 이유를 적고 사용자 결정을 받는다.

**W5-7은 "조사"가 아니라 "요청"이다.** `PointCloud2` 에는 트랙 식별자도 상태도 없다. 제어 PC는 스탬프 간격과 궤적 점프로 대체하는데(L1 §4.4), 이 둘은 **vision이 공을 놓치고 관성 예측만 계속 발행하는 경우에 정확히 반대로 움직인다** — 스탬프는 신선하고 점프는 오히려 작아진다. L1 §4.5의 $\bar\nu$ 도 마찬가지다. 즉 현재 설계에는 유령 트랙을 판별할 수단이 없다.

vision 메시지에 `track_id`(uint32)와 `valid`/`status`(uint8) 필드 **한두 개**를 추가하면 이 문제와 예측 건강도 감시가 동시에 닫힌다. 비용 대비 효과가 압도적이므로, 단계 W에서 이것을 먼저 요청하고 답을 받은 뒤 L1을 확정한다. 거절되면 마스터 §10에 **미해결 위험으로 남긴 채** 진행한다.

**`point_step` 산술이 닫히지 않는다.** 사용자 진술 기준으로 필드를 더하면

| 구성 | 바이트 |
|---|---|
| `x, y, z, vx, vy, vz, ax, ay, az` (float64 × 9) | 72 |
| `cov` (float64 × 36) | 288 |
| 소계 | 360 |
| `t`가 float64이면 | 368 |
| `t`가 uint32이면 | 364 |

인데 진술된 `point_step`은 약 372 B다. 4–8 B가 설명되지 않는다(정렬 패딩일 수도, 아직 언급되지 않은 필드일 수도 있다). **파서를 offset 가정으로 쓰지 않고 `PointField` 배열에서 읽어 구성한다**(L1 §5.1). W5-2에서 실제 덤프로 확정한다.

## 4. 수행 순서

0. **W5-7을 먼저 요청한다.** 답을 받는 데 시간이 걸리므로 가장 먼저 띄운다.
1. **W4-1, W5-2를 먼저 한다.** 각각 "제어기가 어디에 무엇을 쓰는가"와 "무엇을 받는가"를 정하는 항목이라, 나머지 설계가 전부 여기에 매달려 있다.
2. W1 → W2 → W3 순으로 구조·원시형·재사용 대상을 파악한다.
3. W5의 나머지를 실제 토픽 데이터로 확인한다(`ros2 topic echo --once`, rosbag 1회 녹화).
4. W6, W7은 시뮬레이션 착수 직전까지 미뤄도 된다.
5. 기록을 각 layer 문서의 §2 게이트 표와 §10 미확정 항목에 반영하고, 어긋나는 서술을 고친다.
6. 그 다음에야 L0 구현을 시작한다.

동시에, 마스터 §4.1의 **$T_{close,tot}$ 선행 측정(L6a)** 도 이 단계와 병행한다. 그 값이 목표 투척 속도의 실현 가능성을 결정한다.
